## 1. 管线

一个视图的光照部分（场景级的 TLAS 和 cache 更新在前面，0008 §5.2）：

```
材质缓冲（0011 §4） ─┬─ light tile 预采样（场景级）
                     ├─ [L0–L2] VSM：页标记 → 渲染 → 太阳阴影遮罩
                     ├─ ReSTIR：初始采样 → 时域复用 → 配对空间复用 → duplication map
                     ├─ 镜面追踪（低粗糙度）
                     ├─ 最终着色（按 closure bucket，0011 §5.4）→ 解调的漫反射/镜面 + hit distance
                     ├─ 降噪（或 DLSS-RR）
                     ├─ 合成（IBsdf.Compose，0011 §5.6）+ 自发光
                     ├─ 半透明（0009 §8）、体积雾合成（0013 §3）
                     ├─ 超分（TSR / 厂商）
                     └─ 后处理 → 显示变换 → 交给 UI（0008 §6）
```

## 2. 统一路径重采样框架

### 2.1 路径与蓄水池

- 路径 `x0`（相机）→ `x1`（主可见点，来自材质缓冲）→ `x2` → …。
- 一个蓄水池保存一条被选中的路径：
  - 长度 2：`x1` 处的 NEE 直接连到光源，也就是直接光；
  - 长度 ≥ 3：间接光。
- 这就是 PTE §6.1 的统一做法：直接光不再单独跑一套 ReSTIR DI，初始重采样在同一棵路径树里挑一条，DI 和 GI 共用一套复用 pass。

蓄水池格式按 shift 类型分两种：

| 格式 | 档位 | 内容 | 大小 |
|---|---|---|---|
| 重连 | L0–L3 | 重连点 `xk`（位置、八面体法线）、到达 `xk` 的入射辐射亮度（half3）、`W`、confidence `M`、路径长度和类型、光源 id（长度 2 时） | 32 B |
| hybrid | L4 | 上面所有，加随机数种子、重连点下标、lobe 下标、压缩后的辅助量（PTE §6.2.1） | 64 B |

每个视图两份（本帧、上一帧），是视图的历史资源（0007 §8）。

### 2.2 初始采样

每个蓄水池像素：

1. 从材质缓冲读出 `x1` 的 proxy lobe（漫反射反照率、F0、粗糙度、法线，0011 §4.2）。
2. **NEE**：从本 tile 分到的 light tile 里抽 C 个光源候选（C 按档位取 4–32，越往深的弹射越少，PTE §7：`32/2^b`；Falcor 的代码是 `32/v²`，见 §2.10），以 proxy lobe × 光源辐射亮度 × 几何项为 target 做 RIS。不含可见性。
3. **BSDF 采样**：按 proxy lobe 采样方向，发射线得到 `x2`。
4. 在 `x2`：
   - L0、L1：直接查世界 radiance cache 作为入射辐射亮度，路径到此为止；
   - L2 以上：在 `x2` 再做一次 NEE（命中点的材质用简化材质，0011 §9），然后查 cache；
   - L3：再弹射一次；
   - L4：一直弹射到 Russian roulette 终止，或者达到最大深度。
5. 对整棵路径树做 RIS，选出一条路径。
6. 选中的是长度 2 的路径时，补一条阴影射线；选中长度 ≥ 3 的时，`x1→x2` 的可见性已经由那条射线给出。

- Russian roulette 只用在初始采样里，random replay 时不用（PTE §6.2.4）。
- 天空和环境光是一个光源：按天空 LUT 的亮度分布做重要性采样（0013 §1.4）。
- 自发光物体也是光源：自发光三角形表见 §5.2。

### 2.3 shift mapping

- **重连 shift**（L0–L3）：把邻居的样本重连到当前像素的 `x1`；直接光重连到光源顶点，间接光重连到 `x2`。
  - 当前像素的 `x1` 太光滑（proxy 粗糙度 < τ，默认 0.2）时，重连没有意义，这部分交给镜面追踪（§2.7）。
- **hybrid shift**（L4）：在重连之前先用相同的随机数重放路径，直到满足 PTE §4 的两条判据：
  - 双 ray footprint 阈值：`min(正向 footprint, 反向 footprint) ≥ (ε/100) · 主射线 footprint`，ε = 0.02；
  - `x_{k-1}` 的单点粗糙度阈值（0.2）。
  - 这些阈值和场景尺度无关，不需要按场景调。
- 非参数化的 BSDF（例如 Toon，0011 §5.7）没有"粗糙度"，用它的 proxy lobe 的粗糙度作为替代。

### 2.4 时域复用

- 用运动向量把当前像素投影到上一帧，取上一帧的蓄水池作为候选。
- **dual motion vector**（PTE §6.4）：去遮挡的像素再用一个"假设遮挡体和被遮挡面的相对运动一致"的运动向量试一次，减少去遮挡噪声。
- **confidence cap**：
  - 默认 `Cap = 20`，L0、L1 取小一点（10–15），好让样本更快更新。
  - 用 **duplication map** 自适应降低 cap（PTE §5）：每帧结束时，每个像素统计 17×17 邻域里和它共享同一个初始样本的像素数，除以 288 得到分数 `d`；下一帧做时域复用时取 `Cap = lerp(Cap_default, Cap_min, d^λ)`，`Cap_min = 1`，`λ = 0.1`。
  - 判断"共享同一个初始样本"：L4 比较随机数种子；重连格式没有种子，就比较 (重连点位置, 光源 id) 的哈希，这个哈希在初始采样时写进蓄水池的低位。
  - 这会引入一点偏差（论文实测平均 3.25%），换来的是没有相关性斑块。有一个 cvar 可以关掉它，得到无偏的结果（参考对比用）。

### 2.5 配对空间复用

PTE §3：像素 A 从 B 复用时，A 要把 B 的样本 shift 过来，还要把自己的样本 shift 到 B 来算 MIS 权重；这正好也是 B 从 A 复用时要做的两次 shift。所以把像素两两配对，配对的两个像素共享这两次 shift，空间复用的 shift 开销减半。

- **配对纹理**：cook 时生成 3 张大小不同的纹理（254²、230²、210²），每个像素存它的配对邻居的坐标偏移（2×8 位）。偏移近似服从标准差 σ 的正态分布。σ 的取法是让平均距离和半径 r 的均匀圆盘相同：σ√(π/2) = 2r/3，r = 30 时 σ ≈ 16。生成方法是 PTE §3.1 的反复 2×2 洗牌，在 cook 工具里离线完成。
- 每帧对每张纹理随机做翻转、镜像、转置和平移，避免固定图案。
- 邻居数按档位取 1–3，一个邻居用一张纹理。
- 实现分成两个 pass：先把每个像素的路径 shift 到它所有的配对邻居，再做重采样。
- 邻居拒绝：法线夹角、深度差（按视距归一化），以及 proxy 粗糙度差。

### 2.6 最终着色

- **全分辨率着色**：蓄水池分辨率低于全分辨率时，每个全分辨率像素把覆盖它的 1–4 个蓄水池当作候选，用自己的 proxy lobe 再做一次 RIS 选样（"蓄水池上采样"），再用自己的精确 BSDF 着色。
- **精确 BSDF**：按 tile 的 closure bucket 分别 dispatch（0011 §5.4）。重采样用的 target 是 proxy lobe，着色用的是精确 BSDF。`W` 估计的是"样本分布的 1/pdf"，被积函数用精确 BSDF，所以结果仍然无偏；代价是 proxy 和精确 BSDF 差别越大，噪声越大。
- **向量权重去色噪**（PTE §6.3）：空间复用时同时累积 RGB 的重采样权重，着色用它，后续的重采样仍然只用标量权重。
- **输出给降噪器**：
  - 漫反射和镜面分开，各自除以 proxy 的漫反射反照率和预积分的镜面反照率（解调）；
  - 每路带一个 hit distance。
- 最后的可见性：被选中的样本在着色前做一次可见性测试。L0–L1 的空间复用不对邻居做可见性测试，只测最终的样本（有偏，但很常见）；L2 以上对每个被接受的邻居做一次。

### 2.7 镜面追踪

重连 shift 处理不了粗糙度低于 τ 的 lobe（镜子、水面、清漆）。L0–L3 对这部分单独追踪：

- 每个镜面像素按 VNDF 采样一条射线（分辨率按档位取）。
- 命中点：
  - L0–L2：简化材质，加天空和世界 cache；
  - L3：简化材质加一次 NEE；粗糙度 < 0.05 的像素命中后走波前式完整材质（cvar 控制，0011 §9.3）。
- 最终着色时，proxy lobe 里粗糙度低于 τ 的镜面部分从 ReSTIR 的结果里排除，改用镜面追踪的结果。按 lobe 划分，不做 MIS。
- 结果走镜面降噪器。
- L4 不需要这一步：hybrid shift 可以处理镜面路径。

### 2.8 GPU 实现要点

- 采样和复用的代码里尽量用条件选择代替分支（PTE §6.2.1）。
- L4 的 random replay 先对"需要 replay 的 (像素, 邻居) 对"做流压缩，再 dispatch（PTE §6.2.2）。
- L4 强制在 NEE 光源顶点上重连，replay 时不再做光源采样（PTE §6.2.3）。
- 预采样 light tile（Wyman & Panteleev 2021）：场景级 pass 每帧按功率采样出 128 个 tile，每个 tile 1024 个光源；每个 8×8 的屏幕 tile 取其中一个，提高缓存一致性。
- ReSTIR 的 pass 是 compute，射线都是 inline ray query。

### 2.9 路径分类与归属

DI 和 GI 放进同一个蓄水池（§2.1），但不是每个档位、每个项目都让蓄水池负责全部光照：太阳在 L0–L2 走 VSM（§5.3），低粗糙度镜面在 L0–L3 走镜面追踪（§2.7），以后也可能有项目只用 ReSTIR 做直接光、间接光用别的方案（探针、屏幕空间、烘焙）。为此把一个像素收到的光按路径分成几类，每个档位为每一类指定一个**负责者**。

| 类 | 路径 | 说明 |
|---|---|---|
| `E` | `x1` 自身的自发光 | 主可见点是光源或自发光表面 |
| `Dsun` | `x1` → 太阳 | 方向光，包括 BSDF 采样碰到太阳圆盘 |
| `Dnee` | `x1` 处 NEE 连到太阳以外的光源 | 局部光源、自发光三角形（§5.2）、天空 |
| `Dhit` | `x1` 的 BSDF 射线打到光源或天空（`x2` 是光源） | `Dnee` 的 MIS 搭档 |
| `I` | `x1` 的 BSDF 射线打到非光源表面，`x2` 往后反射过来的光 | 间接光；在哪里终止、查不查 cache 按档位（§2.2） |
| `S` | proxy lobe 里粗糙度低于 τ 的镜面部分，所有长度 | §2.7 |

| 类 | L0 | L1 | L2 | L3 | L4 | 外部 GI 配置 |
|---|---|---|---|---|---|---|
| `E` | 着色 | 着色 | 着色 | 着色 | 着色 | 着色 |
| `Dsun` | VSM | VSM | VSM | 蓄水池 | 蓄水池 | VSM 或蓄水池（按档位） |
| `Dnee`、`Dhit` | 蓄水池 | 蓄水池 | 蓄水池 | 蓄水池 | 蓄水池 | 蓄水池 |
| `I` | 蓄水池（`x2` 查 cache） | 同左 | 蓄水池（`x2` NEE + cache） | 蓄水池（2 次弹射） | 蓄水池 | 外部 GI |
| `S` | 镜面追踪 | 镜面追踪 | 镜面追踪 | 镜面追踪 | 蓄水池 | 镜面追踪或外部方案 |

- "着色"指最终着色直接加上，不经过重采样。`E` 永远不进蓄水池（Falcor 也是这样，§2.10）。
- 归属是一个 cvar 掩码（`r.restir.classes`），预设按档位填；蓄水池格式和 pass 不变，掩码只决定初始采样时哪些候选进 RIS、哪些写进残差。
- **R3 的"ReSTIR DI"就是这张表的一种配置**：蓄水池只负责 `Dnee`、`Dhit`，路径长度到 `x2` 为止（BSDF 射线只为了找到光源，`x2` 不是光源就不贡献），`I` 暂时由现在的常数环境光负责。到 R4，`I` 换成蓄水池，代码不用分叉。关掉 ReSTIR 的档位只是把掩码清空，`Dnee`、`Dhit` 改由 clustered 光源网格（§5.4）不带阴影地着色。

约束：

1. **每一类恰好一个负责者**，否则会重复计算或者漏掉。
2. **`Dnee` 和 `Dhit` 的负责者必须相同。**它们是同一个积分的两种采样策略，靠 MIS 合在一起；拆给两个负责者，就会重复计算或者失去 MIS。
3. **外部 GI 只能返回反射光。**它在 `x2` 查到的辐射亮度不能包含光源表（§5.1、§5.2）里的光源和天空自身的发射，那些属于 `Dhit`；也不能包含太阳的直射（属于 `Dsun`），但太阳照亮 `x2` 之后反射的部分要有。反过来，蓄水池负责 `I` 时，SHaRC 的项（§4.1）也要把"自发光"和"反射光"分开存，查询时按需要相加。
4. **太阳由 VSM 负责时**，NEE 的候选里没有太阳，天空的重要性采样排除太阳圆盘，BSDF 射线碰到太阳圆盘在蓄水池里贡献 0。
5. **残差和降噪**：不进蓄水池的部分在最终着色里加上。没有噪声的（`E`、VSM 的 `Dsun`）在降噪之后合成；外部 GI 自带降噪的也在降噪之后合成，否则按漫反射/镜面解调后加进降噪器的输入。Falcor 把残差只写进颜色，不写进降噪器的输入（§2.10），这一点我们不照搬。

### 2.10 Falcor 实现对照

对照 Falcor 9.0 里 ReSTIR PT Enhanced 的实现（`Source/Modules/ReSTIRPathTracing`，由 `Source/RenderPasses/PathTracer` 驱动，`scripts/PathTracerReSTIRPT.py` 是示例配置），记下和本文相关的事实。下面的路径都相对于 Falcor 仓库。

DI 和 GI 怎么合在一起：

- **一个像素一个蓄水池**（`PathReservoir`，`PathReservoir.slang:309`）：M、权重、`integrand`（float3，也就是 f/p 的颜色）、路径标志（一个 uint 打包路径长度、重连顶点下标、`lastVertexNEE`、光源类型、重连点前后的 lobe 信息）、初始随机数种子、重连点的 hit 信息、Jacobian、到达重连点的入射辐射亮度和方向。不压缩约 80 B，压缩后约 64 B，和我们 hybrid 格式的 64 B 一致。
- **初始采样是路径前缀上的流式 RIS**（`PathTracer.slang:831` 起的 `handleHit`）：每个顶点的 NEE 样本和 BSDF 命中的光源各是一个候选，先乘 NEE/BSDF 的 MIS 权重，再按 `integrand` 的亮度做 RIS（`PathReservoir.slang:568`、`651`）。DI 就是长度最短的那些候选，没有单独的 DI 流程。
- **强制在 NEE 光源顶点上重连**（`ReSTIRPT.slang:385`）：主可见点上的 NEE 样本把光源点本身记成重连顶点（重连顶点下标 1），所以 DI 样本做 shift 时**不需要 random replay**，只要一条阴影射线（`ResamplingCommon.slang:646`；`GenerateRetraceWorkload.cs.slang:194` 只把下标大于 1 的样本排进 replay 队列）。这是 DI 和 GI 合并之后 DI 仍然便宜的原因。shift 里对 NEE 光源顶点跳过 footprint 和粗糙度判据，在目标像素重新算光源 pdf 和 NEE/BSDF 的 MIS 权重（`Shift.slang:259`、`328`、`373`）。
- **时域和空间复用不区分 DI 和 GI**，同一套 pass、同一个 `shiftPath`。

能不能只做一部分：

- 有一个选项 `sampleDI`（默认开）：关掉以后，主可见点的 NEE 和第二个顶点碰到的光源、天空不进蓄水池，写进残差 `pathL0`，不经过重采样直接加到颜色上（`ReSTIRPT.slang:356`、`431`、`469`）。也就是"蓄水池只负责 GI，DI 另算"。
- **反过来"只做 DI"的选项没有**；也没有最短路径长度、按长度排除的选项，只有最大弹射数。
- 主可见点的自发光从不进蓄水池（只有 Area ReSTIR 模式例外），走残差。
- 残差只写进颜色，`FetchDenoiserData` 只读蓄水池，**残差不进降噪器的输入**（`FetchDenoiserData.cs.slang:71` 起）。
- 解析光源（点光、方向光）不做 MIS，时域复用时也不支持它们变化（`Shift.slang:350`；`HybridShiftTraceRays.slang:337`）。

所以 §2.9 的归属掩码是 `sampleDI` 的推广：Falcor 只能把 DI 拿出去，我们要能把任意一类交给别的负责者，包括"只做 DI"。

和本文其他各节的出入：

- **NEE 候选数**：§2.2 按 PTE §7 写的是 `32/2^b`；Falcor 的代码是 `max(1, 32/v²)`，v 是顶点下标（`LightTileRISHelper.slang:54`），依次是 32、8、3、2、1。两者在第二个顶点就不同（16 和 8）。先按代码实现，实测之后再定（§14）。
- **duplication map**（§2.4）：Falcor 里默认关掉（`enableDupMapMCapDownweighting`），公式和我们写的一致：17×17 窗口、除以 288、`lerp(Cap, 1, d^0.1)`（`ResamplingCommon.slang:756`）。我们保持默认开。
- **dual motion vector**（§2.4）：Falcor 的实现是按材质的反射概率，在表面运动向量、delta 反射和 delta 透射运动向量里随机选**一个**（`ComputeReuseMotionVector.cs.slang:102`），去遮挡运动向量按 Zeng et al. 2021；不是同时试两个。实现时以代码为准，§2.4 的写法留作对照。
- **向量权重**（§2.6）：Falcor 的 `integrand` 本来就是颜色，RIS 用它的亮度；另有一个默认关闭的 `useDecoupledShading` 累积空间复用里所有候选的颜色贡献。没有专门给降噪用的向量权重，我们 §2.6 的做法是自己的扩展。
- **分辨率**：Falcor 里没有 1/4、1/2、棋盘分辨率的蓄水池，也没有蓄水池上采样（§2.6）。这些是我们自己加的，L0–L2 的质量要单独验证（§13）。
- **其余的优化我们都已采用**，Falcor 里的位置留作实现时参考：
  - 配对空间复用：预先算好的偏移图案，每帧统一做随机平移、翻转和转置；正向 shift 先算一次存进缓冲，逆向直接读邻居的结果（`SpatialPrecomputeShiftBuffer.cs.slang:121`、`SpatialResampling.cs.slang:158`）；
  - replay 工作量压缩：16×16 tile 一组，wave 前缀和压缩，每个 warp 一次原子操作（`GenerateRetraceWorkload.cs.slang:279`）；
  - Russian roulette 只在初始采样里用，replay 时照样消耗随机数但不终止（`PathTracer.slang:787`）；
  - 用条件选择代替分支（`PathReservoir.slang:424`）；
  - 蓄水池按 16×16 tile 内 Morton 序排布（`ReSTIRPathTracingParams.slang:39`）；
  - 光线 payload 只有 20 B（`TracePassMinimalPayload.rt.slang:52`）。

## 4. 世界 radiance cache

### 4.1 SHaRC 式哈希网格

- **键**：世界位置量化到体素，体素大小随到相机的距离按对数分级；再加上法线的粗略方向（6 个主轴方向之一），区分墙的两面。64 位键，开放寻址哈希表。
- **值**：累积的辐射亮度（RGB）、样本数、最后访问的帧号。
- **更新**（场景级，异步计算）：
  - 每帧按"cache 更新比例"抽一部分屏幕像素，从它们出发追踪多次弹射的路径（命中点用简化材质加 NEE，路径在远处查已有的 cache 项），把路径上每个顶点看到的辐射亮度原子累加进对应的项；
  - 一个 resolve pass 把累积量合并进项里，按时间衰减；
  - 很久没被访问的项被清除。
- **查询**：路径在 `x2`（或更深）终止时，查它所在体素的项；查不到就用天空环境光近似。
- 每个视图都从自己的像素里抽样，但所有视图共用一张表。
- 内存：每项约 40 B；2^20 项约 40 MiB。

### 4.2 NRC

- 一个很小的 MLP（例如 4 层 × 64 宽），输入是位置编码、法线、粗糙度、视向，输出辐射亮度。
- 每帧在线训练：训练样本来自 cache 更新路径的长尾部分。
- 推理和训练都用 cooperative vectors（SM 6.9），只在有矩阵单元的平台上启用：
  - NV 的 RTX 显卡、RDNA4、Arc；
  - PS5 Pro 和 NS2 的 tensor core，等平台 API 确认之后。
- 用 target 描述里的 capability 做开关（0005），不在 shader 里写平台分支。没有矩阵单元时退回 SHaRC。

## 5. 直接光

### 5.1 光源

| 类型 | 参数 | 说明 |
|---|---|---|
| 点、球 | 光通量（lm）、半径 | |
| 聚光 | 光通量、内外角、半径 | |
| 矩形、圆盘 | 亮度（nit）、尺寸、可选纹理 | 面光源 |
| 管状 | 光通量、长度、半径 | |
| 方向光（太阳、月亮） | 照度（lux）、角直径 | §5.3 |
| 天空 | 来自大气（0013 §1） | |
| 自发光网格 | 来自材质 | §5.2 |

- 全部用物理单位，曝光见 §8.1。
- 光函数、IES 曲线和 cookie 在 target 函数里也参与计算（它们只是光源方向上的一个乘子），这样暗的方向不会浪费样本。光函数是 LightFunction 材质域（0011 §10）。

### 5.2 自发光三角形

- 材质的拓扑里有自发光 closure 的实例（0011 §3.5），由场景级的 pass 收集它们的三角形，按简化材质图集里的自发光值估计每个三角形的功率，写进一张自发光三角形表。
- light tile 预采样把它们和解析光源放在一起，按功率采样。
- 只收集 RT LOD 的三角形，数量受控；没被收集的小自发光物体靠 GI 路径命中来照亮场景。

### 5.3 太阳

**L0–L2：VSM，只用于方向光。**

- clipmap：每级的虚拟分辨率是 16K²，页大小 128²。
- **页标记**：从深度缓冲重建世界位置，标记需要的页（也包括半透明和体积雾请求的页）。
- **页分配**：从物理页池里分配。物理页池的大小按平台定，NS2 4K²，XSS 6K²，PS5/XSX/PC 8K²。
- **渲染**：用 cluster DAG 的可见性管线（0009 §4），按页的分辨率选 LOD，HW 和 SW 光栅写进页池。
- **缓存**：静态物体的页跨帧保留；动态实例的包围盒覆盖到的页，以及太阳方向变化时，相应的页失效。
- **过滤**：L0 用 PCF；L1–L2 用少量样本的 shadow map ray marching（SMRT 式）得到接触硬化的软阴影。
- 结果写成一张屏幕空间的太阳阴影遮罩。ReSTIR 的 target 和着色里，太阳作为一个"预先算好可见性"的光源处理：不参与重采样，直接加到最终着色上。

**L3 以上**：太阳进 ReSTIR，和其他光源一样。阴影射线在太阳的角直径内做锥形采样，得到软阴影。不分配 VSM。

- 云的阴影（0013 §2.4）在两条路径里都是一个乘子。

### 5.4 clustered 光源网格

- 一个视锥对齐的 3D 网格（例如 16×9×24），每个格子列出影响它的局部光源。
- 不透明物体的光照不用它，它是给这些路径用的：
  - 半透明（0009 §8）；
  - 体积雾（0013 §3）；
  - 粒子（0013 §8）；
  - 毛发（0013 §7）。
- 这些路径的阴影：太阳用 VSM 或 RT；局部光源 L2 以下不投影，L3 以上每像素打一条阴影射线，按重要性随机选一盏光。

## 6. 降噪

自研，ReBLUR/ReLAX 那一类，漫反射和镜面两路分开：

- **输入**：
  - 解调后的辐射亮度和 hit distance；
  - 法线和粗糙度（来自 proxy lobe）；
  - 深度、运动向量、去遮挡遮罩（来自 dual motion vector）。
- **时域累积**：
  - 历史是视图的历史资源；
  - 漫反射按表面运动重投影；镜面按 hit distance 和粗糙度推算出的虚拟运动重投影；
  - 累积帧数随时间增长，去遮挡时清零。
- **历史校正**：用邻域方差夹住历史，加上抗萤火虫。
- **空间滤波**：自适应半径的泊松或 à-trous，半径随 hit distance、粗糙度和累积帧数变化。
- **去遮挡修复**：累积帧数少的像素，用更大的空间半径和低 mip 的历史来补。
- **输出**：降噪后的解调信号，交给合成（0011 §5.6）。
- 低分辨率蓄水池的档位：降噪在全分辨率上做，因为着色已经是全分辨率的（§2.6）。

**DLSS Ray Reconstruction**（NV 上可选）：`Upscaler::caps().denoises` 为真时，graph 不声明降噪器和 TSR，直接把带噪声的漫反射、镜面和引导信息（反照率、法线、粗糙度、镜面 hit distance、运动、深度）交给它。

## 7. 超分、抗锯齿、帧生成

### 7.1 TSR

自研的时域超分，是全平台的基线：

- **输入**：内部分辨率的颜色（已合成半透明）、深度、运动向量、reactive mask（0009 §8）、曝光。
- **抖动**：Halton(2,3)，相位数随超分倍率变化（8–32）。
- **历史**：保存在显示分辨率上，是视图的历史资源。
- **重投影和校正**：在 YCoCg 空间里按方差裁剪；细线和高光的闪烁用亮度历史抑制。
- **锐化**：可选，在输出前做一次自适应锐化。
- 动态分辨率下内部分辨率每帧都可能变，TSR 在每帧的抖动和缩放里处理这一点，历史不需要重建。

### 7.2 `Upscaler` trait

```rust
pub trait Upscaler: Send + Sync {
    fn caps(&self) -> UpscalerCaps;     // 支持的倍率、是否自带降噪（RR）、要不要 reactive mask
    fn render_size(&self, display: UVec2, mode: UpscaleMode) -> UVec2;
    fn jitter(&self, frame: u64, render: UVec2, display: UVec2) -> Vec2;
    fn add_passes<'g>(&self, g: &mut RenderGraph<'g>, view: ViewId, inputs: &UpscaleInputs<'g>)
        -> TextureHandle<'g>;
}
```

| 实现 | 平台 | 位置 |
|---|---|---|
| TSR | 全部 | `marlin-render` |
| DLSS SR / RR | PC（NV）、NS2 | PC：`render_ext/dlss`（cargo feature）；NS2：`platforms/switch2` |
| FSR 4 | PC（RDNA4） | `render_ext/fsr` |
| XeSS | PC（Arc） | `render_ext/xess` |
| PSSR 2 | PS5 Pro | `platforms/ps5` |

- 厂商 SDK 要直接拿到原生的 command list 和资源。graph 需要一种"外部" pass：声明读写和要求的状态，执行闭包里通过 `ctx.native()` 拿到原生句柄（0007 要补，§14）。
- 厂商 SDK 都是 C 接口的动态库或静态库，从 no_std 的 runtime 里通过 FFI 调用。

### 7.3 动态分辨率与帧生成

- **动态分辨率**：一个 PI 控制器以上一帧可用的 GPU 计时为输入，按视图调整内部分辨率的缩放。历史资源按最大内部分辨率分配，缩放只改视口，不重建资源。
- **帧生成**：只在 PC 上做，用 DLSS FG 或 FSR FG。它接在 present 路径上，和延迟手段（0008 §3.4）一起配置。接口形状待定（§14）。

## 8. 后处理与显示变换

### 8.1 曝光

- 物理相机：ISO、快门、光圈，换算成 EV100；DOF 和运动模糊用同一组参数。
- 自动曝光：在异步计算上算亮度直方图，按测光模式加权，时间上平滑；可以被手动 EV100 和补偿覆盖。
- 曝光在超分之前乘进颜色（预曝光），超分和 DLSS 都需要这样的输入。

### 8.2 后处理链

```
超分输出 ─▶ DOF（scatter-as-gather，物理 CoC）─▶ 运动模糊（tile 最大速度）─▶ bloom
        ─▶ [PostProcess 材质：BeforeDisplay] ─▶ 显示变换（含调色 LUT）
        ─▶ [PostProcess 材质：AfterDisplay] ─▶ 胶片颗粒、暗角 ─▶ ViewOutput
```

- DOF 和运动模糊放在超分之后，在显示分辨率上做，这也是 DLSS 推荐的顺序。
- bloom：降采样和升采样链（0007 §11.2 的验收链）；Ultra 以上可以选 FFT 卷积 bloom，支持任意的光晕形状。
- 后处理材质的注入点见 0011 §10.2。

### 8.3 显示变换（可编程）

```csharp
public interface IDisplayTransform
{
    // 输入：已乘曝光的场景线性 Rec.709；输出：目标显示空间里的线性值（编码之前）
    float3 Apply(float3 sceneLinear, in DisplayParams d);

    // true：烘成 3D LUT；false：逐像素求值（需要做局部色调映射这类空间相关的操作时）
    const bool BakeToLut = true;
}

public struct DisplayParams
{
    public DisplayEncoding Encoding;   // Srgb / Pq / ScRgb
    public ColorGamut Gamut;           // Rec709 / P3 / Rec2020
    public float PeakNits, MinNits, PaperWhiteNits;
}
```

- 显示变换是一个**可编程的接口**，归在 PostProcess 材质域（0011 §10.2）。项目可以提供自己的实现（AgX、GT7 式，或者完全自定义的），不需要改引擎。
- 引擎自带两个实现：
  - `Aces2`：ACES 2.0 的输出变换，按峰值亮度参数化，同一张画面输出 SDR、HDR10 和 scRGB，带色域压缩。这是默认实现。
  - `Neutral`：一个色相稳定的中性 look（PBR Neutral 那一类），给产品展示、材质预览用。
- **LUT 烘焙**：`BakeToLut` 为真时，`Apply` 只在一张 65³ 的 3D LUT（输入在 log2 空间）上运行，调色 LUT 也合并进去；参数不变就不重烘。逐像素的成本只是一次 3D 纹理采样。
- 输出编码（sRGB 曲线、PQ、scRGB 线性）由引擎在最后一步统一做，`Apply` 只输出线性值。
- 调色的 LUT 由美术在外部工具里制作，作为 3D 纹理资产导入。
- 具体的语法形状（接口名、`const bool` 静态参数的写法）沿用 0004 §13.3，接口名要和 0011 的材质域一起确认（§14）。

## 9. 色彩

- 工作空间是**线性 Rec.709**。颜色纹理按 sRGB 制作，采样时由硬件转成线性。
- 光源颜色可以给色温（K），在 CPU 端换算成 Rec.709。
- HDR 输出的参数（峰值亮度、paper white、色域）来自平台的显示查询，或者玩家的 HDR 校准界面，作为 `DisplayParams` 传给显示变换。
- UI 在显示变换之后合成，在 sRGB 编码空间里混合（0012 §8）。

## 10. 异步计算编排

可以和光栅重叠、标成 `b.async_compute()` 的 pass：

| pass | 和什么重叠 |
|---|---|
| BLAS refit / 构建、TLAS 构建 | 可见性管线（visbuffer 光栅） |
| radiance cache 更新 | 可见性管线、材质解算 |
| light tile 预采样、自发光三角形收集 | 可见性管线 |
| 天空 LUT、云的天气图（0013） | 整帧前半段 |

| VSM 页标记之后的静态页检查 | 材质解算 |

## 12. 参考路径追踪器

- editor 里的一个视图调试模式：无偏、多次弹射，命中点一律用波前式完整材质，每帧 1 spp，相机静止时累积。
- 和 L4 用同一套 BSDF、TLAS 和材质解算代码，只是没有任何复用和缓存。
- 用途：
  - 给各档位的实时结果提供 ground truth；
  - 测试里做数值对比（§13）；
  - 美术用它校对材质。

## 13. 测试

- **平台无关**：
  - 配对纹理：每个像素的配对是互逆的（A↔B），偏移的分布接近目标 σ，可以平铺；
  - duplication map 的统计和 cap 公式；
  - 光源单位换算、色温换算、EV100；
  - ACES 2.0 实现和官方参考值对比（CPU 上逐点比较）；
  - TSR 的抖动序列和缩放。
- **平台相关**（真实硬件）：
  - **无偏性**：关掉去相关后，L2/L3/L4 累积足够多帧的结果和参考路径追踪器的结果做 FLIP/MSE 比较，误差在阈值内；
  - proxy target 和精确 target 收敛到同一个结果（只有噪声不同）；
  - 降噪器：静态场景累积若干帧后，和参考结果的误差有上界；
  - 显示变换烘焙成 LUT 和逐像素求值的结果一致（量化误差之内）；
  - 镜面追踪和 ReSTIR 的 lobe 划分不重复计数：粗糙度跨过 τ 时亮度连续。

## 14. 待定

- §3 和 §11 的数值要在主机上实测之后再调：
  - L0/L1 能不能在 NS2 上撑住；
  - PS5 的 60fps 预设具体降哪一项。

- ReGIR（世界网格的光源蓄水池）作为 light tile 的补充，在光源极多的场景里是否需要。
- NRC 在 PS5 Pro 和 NS2 上的可用性，取决于平台 API。
- graph 的"外部" pass（§7.2）：0007 要补这个 pass 类型。
- 帧生成的接口形状。
- 体积雾里要不要也用 ReSTIR（现在是 clustered 光源加 RIS，0013 §3）。
- `IDisplayTransform`、`DisplayParams` 的名字和形状要和 shader 语言的约定一起确认（0004 的规则：语言相关的命名先问再定）。
