## 1. 管线

一个视图的光照部分（场景级的 TLAS 和 cache 更新在前面，0008 §5.2）：

```
材质缓冲（0011 §4） ─┬─ light tile 预采样（场景级）
                     ├─ [L0–L2] VSM：页标记 → 渲染 → 太阳阴影遮罩
                     ├─ ReSTIR：初始采样 → 时域复用 → 配对空间复用 → duplication map
                     ├─ 镜面追踪（低粗糙度）
                     ├─ 最终着色（按 closure bucket，0011 §5.4）→ 解调的漫反射/镜面 + hit distance
                     ├─ 降噪（或 DLSS-RR）
                     ├─ 合成（IBsdf.Compose，0011 §5.6）+ 自发光
                     ├─ 半透明（0009 §8）、体积雾合成（0013 §3）
                     ├─ 超分（TSR / 厂商）
                     └─ 后处理 → 显示变换 → 交给 UI（0008 §6）
```

## 2. 统一路径重采样框架

### 2.1 路径与蓄水池

- 路径 `x0`（相机）→ `x1`（主可见点，来自材质缓冲）→ `x2` → …。
- 一个蓄水池保存一条被选中的路径：
  - 长度 2：`x1` 处的 NEE 直接连到光源，也就是直接光；
  - 长度 ≥ 3：间接光。
- 这就是 PTE §6.1 的统一做法：直接光不再单独跑一套 ReSTIR DI，初始重采样在同一棵路径树里挑一条，DI 和 GI 共用一套复用 pass。

蓄水池格式按 shift 类型分两种：

| 格式 | 档位 | 内容 | 大小 |
|---|---|---|---|
| 重连 | L0–L3 | 重连点 `xk`（位置、八面体法线）、到达 `xk` 的入射辐射亮度（half3）、`W`、confidence `M`、路径长度和类型、光源 id（长度 2 时） | 32 B |
| hybrid | L4 | 上面所有，加随机数种子、重连点下标、lobe 下标、压缩后的辅助量（PTE §6.2.1） | 64 B |

每个视图两份（本帧、上一帧），是视图的历史资源（0007 §8）。

### 2.2 初始采样

每个蓄水池像素：

1. 从材质缓冲读出 `x1` 的 proxy lobe（漫反射反照率、F0、粗糙度、法线，0011 §4.2）。
2. **NEE**：从本 tile 分到的 light tile 里抽 C 个光源候选（C 按档位取 4–32，越往深的弹射越少，PTE §7：`32/2^b`；Falcor 的代码是 `32/v²`，见 §2.10），以 proxy lobe × 光源辐射亮度 × 几何项为 target 做 RIS。不含可见性。
3. **BSDF 采样**：按 proxy lobe 采样方向，发射线得到 `x2`。
4. 在 `x2`：
   - L0、L1：直接查世界 radiance cache 作为入射辐射亮度，路径到此为止；
   - L2 以上：在 `x2` 再做一次 NEE（命中点的材质用简化材质，0011 §9），然后查 cache；
   - L3：再弹射一次；
   - L4：一直弹射到 Russian roulette 终止，或者达到最大深度。
5. 对整棵路径树做 RIS，选出一条路径。
6. 选中的是长度 2 的路径时，补一条阴影射线；选中长度 ≥ 3 的时，`x1→x2` 的可见性已经由那条射线给出。

- Russian roulette 只用在初始采样里，random replay 时不用（PTE §6.2.4）。
- 天空和环境光是一个光源：按天空 LUT 的亮度分布做重要性采样（0013 §1.4）。
- 自发光物体也是光源：自发光三角形表见 §5.2。

### 2.3 shift mapping

- **重连 shift**（L0–L3）：把邻居的样本重连到当前像素的 `x1`；直接光重连到光源顶点，间接光重连到 `x2`。
  - 当前像素的 `x1` 太光滑（proxy 粗糙度 < τ，默认 0.2）时，重连没有意义，这部分交给镜面追踪（§2.7）。
- **hybrid shift**（L4）：在重连之前先用相同的随机数重放路径，直到满足 PTE §4 的两条判据：
  - 双 ray footprint 阈值：`min(正向 footprint, 反向 footprint) ≥ (ε/100) · 主射线 footprint`，ε = 0.02；
  - `x_{k-1}` 的单点粗糙度阈值（0.2）。
  - 这些阈值和场景尺度无关，不需要按场景调。
- 非参数化的 BSDF（例如 Toon，0011 §5.7）没有"粗糙度"，用它的 proxy lobe 的粗糙度作为替代。

### 2.4 时域复用

- 用运动向量把当前像素投影到上一帧，取上一帧的蓄水池作为候选。
- **dual motion vector**（PTE §6.4）：去遮挡的像素再用一个"假设遮挡体和被遮挡面的相对运动一致"的运动向量试一次，减少去遮挡噪声。
- **confidence cap**：
  - 默认 `Cap = 20`，L0、L1 取小一点（10–15），好让样本更快更新。
  - 用 **duplication map** 自适应降低 cap（PTE §5）：每帧结束时，每个像素统计 17×17 邻域里和它共享同一个初始样本的像素数，除以 288 得到分数 `d`；下一帧做时域复用时取 `Cap = lerp(Cap_default, Cap_min, d^λ)`，`Cap_min = 1`，`λ = 0.1`。
  - 判断"共享同一个初始样本"：L4 比较随机数种子；重连格式没有种子，就比较 (重连点位置, 光源 id) 的哈希，这个哈希在初始采样时写进蓄水池的低位。
  - 这会引入一点偏差（论文实测平均 3.25%），换来的是没有相关性斑块。有一个 cvar 可以关掉它，得到无偏的结果（参考对比用）。

### 2.5 配对空间复用

PTE §3：像素 A 从 B 复用时，A 要把 B 的样本 shift 过来，还要把自己的样本 shift 到 B 来算 MIS 权重；这正好也是 B 从 A 复用时要做的两次 shift。所以把像素两两配对，配对的两个像素共享这两次 shift，空间复用的 shift 开销减半。

- **配对纹理**（R3c3 已实现，§5.8）：cook 时生成 3 张大小不同的纹理（254²、230²、210²），每个像素存它的配对邻居的坐标偏移（2×8 位）。偏移近似服从标准差 σ 的正态分布。σ 的取法是让平均距离和半径 r 的均匀圆盘相同：σ√(π/2) = 2r/3，r = 30 时 σ ≈ 16。生成方法是 PTE §3.1 的反复 2×2 洗牌，在 cook 工具里离线完成。
- 每帧对每张纹理随机做翻转、镜像、转置和平移，避免固定图案。
- 邻居数按档位取 1–3，一个邻居用一张纹理。
- 实现分成两个 pass：先把每个像素的路径 shift 到它所有的配对邻居，再做重采样。
- 邻居拒绝：法线夹角、深度差（按视距归一化），以及 proxy 粗糙度差。

### 2.6 最终着色

- **全分辨率着色**：蓄水池分辨率低于全分辨率时，每个全分辨率像素把覆盖它的 1–4 个蓄水池当作候选，用自己的 proxy lobe 再做一次 RIS 选样（"蓄水池上采样"），再用自己的精确 BSDF 着色。
- **精确 BSDF**：按 tile 的 closure bucket 分别 dispatch（0011 §5.4）。重采样用的 target 是 proxy lobe，着色用的是精确 BSDF。`W` 估计的是"样本分布的 1/pdf"，被积函数用精确 BSDF，所以结果仍然无偏；代价是 proxy 和精确 BSDF 差别越大，噪声越大。
- **向量权重去色噪**（PTE §6.3）：空间复用时同时累积 RGB 的重采样权重，着色用它，后续的重采样仍然只用标量权重。
- **输出给降噪器**：
  - 漫反射和镜面分开，各自除以 proxy 的漫反射反照率和预积分的镜面反照率（解调）；
  - 每路带一个 hit distance。
- 最后的可见性：被选中的样本在着色前做一次可见性测试。L0–L1 的空间复用不对邻居做可见性测试，只测最终的样本（有偏，但很常见）；L2 以上对每个被接受的邻居做一次。

### 2.7 镜面追踪

重连 shift 处理不了粗糙度低于 τ 的 lobe（镜子、水面、清漆）。L0–L3 对这部分单独追踪：

- 每个镜面像素按 VNDF 采样一条射线（分辨率按档位取）。
- 命中点：
  - L0–L2：简化材质，加天空和世界 cache；
  - L3：简化材质加一次 NEE；粗糙度 < 0.05 的像素命中后走波前式完整材质（cvar 控制，0011 §9.3）。
- 最终着色时，proxy lobe 里粗糙度低于 τ 的镜面部分从 ReSTIR 的结果里排除，改用镜面追踪的结果。按 lobe 划分，不做 MIS。
- 结果走镜面降噪器。
- L4 不需要这一步：hybrid shift 可以处理镜面路径。

### 2.8 GPU 实现要点

- 采样和复用的代码里尽量用条件选择代替分支（PTE §6.2.1）。
- L4 的 random replay 先对"需要 replay 的 (像素, 邻居) 对"做流压缩，再 dispatch（PTE §6.2.2）。
- L4 强制在 NEE 光源顶点上重连，replay 时不再做光源采样（PTE §6.2.3）。
- 预采样 light tile（Wyman & Panteleev 2021）：场景级 pass 每帧按功率采样出 128 个 tile，每个 tile 1024 个光源；每个 8×8 的屏幕 tile 取其中一个，提高缓存一致性。
- ReSTIR 的 pass 是 compute，射线都是 inline ray query。

### 2.9 路径分类与归属

DI 和 GI 放进同一个蓄水池（§2.1），但不是每个档位、每个项目都让蓄水池负责全部光照：太阳在 L0–L2 走 VSM（§5.3），低粗糙度镜面在 L0–L3 走镜面追踪（§2.7），以后也可能有项目只用 ReSTIR 做直接光、间接光用别的方案（探针、屏幕空间、烘焙）。为此把一个像素收到的光按路径分成几类，每个档位为每一类指定一个**负责者**。

| 类 | 路径 | 说明 |
|---|---|---|
| `E` | `x1` 自身的自发光 | 主可见点是光源或自发光表面 |
| `Dsun` | `x1` → 太阳 | 方向光，包括 BSDF 采样碰到太阳圆盘 |
| `Dnee` | `x1` 处 NEE 连到太阳以外的光源 | 局部光源、自发光三角形（§5.2）、天空 |
| `Dhit` | `x1` 的 BSDF 射线打到光源或天空（`x2` 是光源） | `Dnee` 的 MIS 搭档 |
| `I` | `x1` 的 BSDF 射线打到非光源表面，`x2` 往后反射过来的光 | 间接光；在哪里终止、查不查 cache 按档位（§2.2） |
| `S` | proxy lobe 里粗糙度低于 τ 的镜面部分，所有长度 | §2.7 |

| 类 | L0 | L1 | L2 | L3 | L4 | 外部 GI 配置 |
|---|---|---|---|---|---|---|
| `E` | 着色 | 着色 | 着色 | 着色 | 着色 | 着色 |
| `Dsun` | VSM | VSM | VSM | 蓄水池 | 蓄水池 | VSM 或蓄水池（按档位） |
| `Dnee`、`Dhit` | 蓄水池 | 蓄水池 | 蓄水池 | 蓄水池 | 蓄水池 | 蓄水池 |
| `I` | 蓄水池（`x2` 查 cache） | 同左 | 蓄水池（`x2` NEE + cache） | 蓄水池（2 次弹射） | 蓄水池 | 外部 GI |
| `S` | 镜面追踪 | 镜面追踪 | 镜面追踪 | 镜面追踪 | 蓄水池 | 镜面追踪或外部方案 |

- "着色"指最终着色直接加上，不经过重采样。`E` 永远不进蓄水池（Falcor 也是这样，§2.10）。
- 归属是一个 cvar 掩码（`r.restir.classes`），预设按档位填；蓄水池格式和 pass 不变，掩码只决定初始采样时哪些候选进 RIS、哪些写进残差。
- **R3 的"ReSTIR DI"就是这张表的一种配置**：蓄水池只负责 `Dnee`、`Dhit`，路径长度到 `x2` 为止（BSDF 射线只为了找到光源，`x2` 不是光源就不贡献），`I` 暂时由现在的常数环境光负责。到 R4，`I` 换成蓄水池，代码不用分叉。关掉 ReSTIR 的档位只是把掩码清空，`Dnee`、`Dhit` 改由 clustered 光源网格（§5.4）不带阴影地着色。

约束：

1. **每一类恰好一个负责者**，否则会重复计算或者漏掉。
2. **`Dnee` 和 `Dhit` 的负责者必须相同。**它们是同一个积分的两种采样策略，靠 MIS 合在一起；拆给两个负责者，就会重复计算或者失去 MIS。
3. **外部 GI 只能返回反射光。**它在 `x2` 查到的辐射亮度不能包含光源表（§5.1、§5.2）里的光源和天空自身的发射，那些属于 `Dhit`；也不能包含太阳的直射（属于 `Dsun`），但太阳照亮 `x2` 之后反射的部分要有。反过来，蓄水池负责 `I` 时，SHaRC 的项（§4.1）也要把"自发光"和"反射光"分开存，查询时按需要相加。
4. **太阳由 VSM 负责时**，NEE 的候选里没有太阳，天空的重要性采样排除太阳圆盘，BSDF 射线碰到太阳圆盘在蓄水池里贡献 0。
5. **残差和降噪**：不进蓄水池的部分在最终着色里加上。没有噪声的（`E`、VSM 的 `Dsun`）在降噪之后合成；外部 GI 自带降噪的也在降噪之后合成，否则按漫反射/镜面解调后加进降噪器的输入。Falcor 把残差只写进颜色，不写进降噪器的输入（§2.10），这一点我们不照搬。

### 2.10 Falcor 实现对照

对照 Falcor 9.0 里 ReSTIR PT Enhanced 的实现（`Source/Modules/ReSTIRPathTracing`，由 `Source/RenderPasses/PathTracer` 驱动，`scripts/PathTracerReSTIRPT.py` 是示例配置），记下和本文相关的事实。下面的路径都相对于 Falcor 仓库。

DI 和 GI 怎么合在一起：

- **一个像素一个蓄水池**（`PathReservoir`，`PathReservoir.slang:309`）：M、权重、`integrand`（float3，也就是 f/p 的颜色）、路径标志（一个 uint 打包路径长度、重连顶点下标、`lastVertexNEE`、光源类型、重连点前后的 lobe 信息）、初始随机数种子、重连点的 hit 信息、Jacobian、到达重连点的入射辐射亮度和方向。不压缩约 80 B，压缩后约 64 B，和我们 hybrid 格式的 64 B 一致。
- **初始采样是路径前缀上的流式 RIS**（`PathTracer.slang:831` 起的 `handleHit`）：每个顶点的 NEE 样本和 BSDF 命中的光源各是一个候选，先乘 NEE/BSDF 的 MIS 权重，再按 `integrand` 的亮度做 RIS（`PathReservoir.slang:568`、`651`）。DI 就是长度最短的那些候选，没有单独的 DI 流程。
- **强制在 NEE 光源顶点上重连**（`ReSTIRPT.slang:385`）：主可见点上的 NEE 样本把光源点本身记成重连顶点（重连顶点下标 1），所以 DI 样本做 shift 时**不需要 random replay**，只要一条阴影射线（`ResamplingCommon.slang:646`；`GenerateRetraceWorkload.cs.slang:194` 只把下标大于 1 的样本排进 replay 队列）。这是 DI 和 GI 合并之后 DI 仍然便宜的原因。shift 里对 NEE 光源顶点跳过 footprint 和粗糙度判据，在目标像素重新算光源 pdf 和 NEE/BSDF 的 MIS 权重（`Shift.slang:259`、`328`、`373`）。
- **时域和空间复用不区分 DI 和 GI**，同一套 pass、同一个 `shiftPath`。

能不能只做一部分：

- 有一个选项 `sampleDI`（默认开）：关掉以后，主可见点的 NEE 和第二个顶点碰到的光源、天空不进蓄水池，写进残差 `pathL0`，不经过重采样直接加到颜色上（`ReSTIRPT.slang:356`、`431`、`469`）。也就是"蓄水池只负责 GI，DI 另算"。
- **反过来"只做 DI"的选项没有**；也没有最短路径长度、按长度排除的选项，只有最大弹射数。
- 主可见点的自发光从不进蓄水池（只有 Area ReSTIR 模式例外），走残差。
- 残差只写进颜色，`FetchDenoiserData` 只读蓄水池，**残差不进降噪器的输入**（`FetchDenoiserData.cs.slang:71` 起）。
- 解析光源（点光、方向光）不做 MIS，时域复用时也不支持它们变化（`Shift.slang:350`；`HybridShiftTraceRays.slang:337`）。

所以 §2.9 的归属掩码是 `sampleDI` 的推广：Falcor 只能把 DI 拿出去，我们要能把任意一类交给别的负责者，包括"只做 DI"。

和本文其他各节的出入：

- **NEE 候选数**：§2.2 按 PTE §7 写的是 `32/2^b`；Falcor 的代码是 `max(1, 32/v²)`，v 是顶点下标（`LightTileRISHelper.slang:54`），依次是 32、8、3、2、1。两者在第二个顶点就不同（16 和 8）。先按代码实现，实测之后再定（§14）。
- **duplication map**（§2.4）：Falcor 里默认关掉（`enableDupMapMCapDownweighting`），公式和我们写的一致：17×17 窗口、除以 288、`lerp(Cap, 1, d^0.1)`（`ResamplingCommon.slang:756`）。我们保持默认开。
- **dual motion vector**（§2.4）：Falcor 的实现是按材质的反射概率，在表面运动向量、delta 反射和 delta 透射运动向量里随机选**一个**（`ComputeReuseMotionVector.cs.slang:102`），去遮挡运动向量按 Zeng et al. 2021；不是同时试两个。实现时以代码为准，§2.4 的写法留作对照。
- **向量权重**（§2.6）：Falcor 的 `integrand` 本来就是颜色，RIS 用它的亮度；另有一个默认关闭的 `useDecoupledShading` 累积空间复用里所有候选的颜色贡献。没有专门给降噪用的向量权重，我们 §2.6 的做法是自己的扩展。
- **分辨率**：Falcor 里没有 1/4、1/2、棋盘分辨率的蓄水池，也没有蓄水池上采样（§2.6）。这些是我们自己加的，L0–L2 的质量要单独验证（§13）。
- **其余的优化我们都已采用**，Falcor 里的位置留作实现时参考：
  - 配对空间复用：预先算好的偏移图案，每帧统一做随机平移、翻转和转置；正向 shift 先算一次存进缓冲，逆向直接读邻居的结果（`SpatialPrecomputeShiftBuffer.cs.slang:121`、`SpatialResampling.cs.slang:158`）；
  - replay 工作量压缩：16×16 tile 一组，wave 前缀和压缩，每个 warp 一次原子操作（`GenerateRetraceWorkload.cs.slang:279`）；
  - Russian roulette 只在初始采样里用，replay 时照样消耗随机数但不终止（`PathTracer.slang:787`）；
  - 用条件选择代替分支（`PathReservoir.slang:424`）；
  - 蓄水池按 16×16 tile 内 Morton 序排布（`ReSTIRPathTracingParams.slang:39`）；
  - 光线 payload 只有 20 B（`TracePassMinimalPayload.rt.slang:52`）。

### 2.11 R4c 的实现：统一 DI+GI 蓄水池（2026-10-19）

`RestirDi::gi`（默认开）。蓄水池在 R3c 的 `Dnee` 之外还负责 `I` 和天空的 `Dhit`（§2.9 的表）。定下的细节：

- **样本有三种**，放在同一个蓄水池里（`PathReservoir`，48 B，比 R3c 的 32 B 多一个点和一个辐射亮度）：
  - 光源：行号和球面上的点，同 R3c；
  - 表面：BSDF 弹射到达的 `x2`，存位置、法线，以及从它射向 `x1` 的辐射亮度；
  - 天空：方向和天空的亮度。

  辐射亮度用 RGB9E5 存一个字，指数偏移取 10 而不是 15（范围 2^−19 到约 2·10^6 nit，覆盖灯具表面）。
- **表面样本按 `x2` 处的面积测度**：target = albedo/π · cosθ₁ · L · cosθ₂ / d²。这样复用时把它重连到别的像素的 `x1`（时域、配对空间、棋盘上采样），和光源样本的点一样，target 里已经含了 Jacobian，复用的代码不用分样本种类，只是 `SampleContribution`、`SampleVisible` 按种类求值。余弦采样的 BSDF 射线转成面积测度的 pdf 是 cosθ₁/π · cosθ₂/d²，所以候选的权重 target/pdf 就是 luminance(albedo · L)。天空样本按立体角（每个像素看到的方向相同）。d² 下限 10^−4，避免墙角处的奇点。
- **初始采样分两个 pass**：`RestirInitial`（光源候选，同 R3c）→ `RestirInitialVisibility`（同 R3c）→ `RestirInitialGi`：从 `x1` 按余弦分布弹射一次，得到一个表面或天空候选，和前面留下的光源样本做 RIS 合并（M 仍为 1）。光源候选和表面/天空候选的定义域不相交，各自的 MIS 权重就是 1/C 和 1。和 `RestirInitialVisibility` 一样单独一个 pass，不把光线查询放进光源候选的循环里。
- **`x2` 的辐射亮度**（`RadianceAt`）：
  - `gi_bounce` 开（L2 以上，默认）：自发光 + `x2` 的 NEE（太阳一条阴影射线，局部光源从 light tile 里 RIS 选一个）+ 反照率 × 再弹射一次到 `x3` 的结果（`x3` 的自发光 + cache；打空则是天空）；
  - `gi_bounce` 关（L0、L1）：自发光 + cache 在 `x2` 的值。

  cache 里没有这一项时用反照率 × 天空近似。NEE 代码和 SHaRC 的更新共用（`Lighting/Paths.mshader` 的 `NextEvent`）。
- **天空进蓄水池以后，光照 pass 不再加环境光**（`RenderSide` 和测试 harness 在 GI 开着时把 `ambient` 置 0）。太阳在 L0–L2 仍是 VSM 的（`Dsun`），BSDF 射线不会碰到太阳圆盘，因为天空是均匀的，本来就没有圆盘（§2.9 第 4 条）。没有局部光源时 ReSTIR 也要运行（只有 GI 候选），SHaRC 每帧更新。
- **离开表面的射线剔除背面**（GI 弹射、阴影和可见性射线，`RayFlags.CullBackFace`）：RT LOD 比光栅化的网格粗，在凹处它高出画出来的表面，从那里出发的射线会先打到它的背面。TLAS 实例不再关掉朝向剔除，只强制不透明。闭合物体照样挡光：射进去先碰正面。单面的几何从背后看会漏光，这是常见的取舍。
- **推送常量的上限**：`RestirArgs` 加上命中点的来源、简化材质和 cache 以后超过 128 B，所以这三样放进一个 uniform（`GiSources`），推送常量里只留一个索引。uniform 里的 `float4` 不能跨 16 字节的行，所以 `SharcSources` 的 `Eye` 放到最前面。
- **为什么还不用 wavefront**（0011 §9.3，用户问过）：L0–L2 的 GI 是漫反射，命中点只要反照率和自发光，简化材质图集一次读取就够，各材质之间没有分歧。按材质分箱、跑完整的 `Surface` 留给 R4d 的镜面（L3 粗糙度 < 0.05）和 L4 的路径追踪。如果 profiler 显示 `RestirInitialGi` 的光线查询拖低了占用率，先像 `RestirInitialVisibility` 那样拆 pass。
- **测试**（marlin-material 的 `gi.rs`，Cornell box，CPU 参考是新的 `reference::global_illumination`：Lambert 路径追踪，每个顶点对每个光源做 NEE，三次弹射后 Russian roulette，每隔 4 个像素算一个，每个 256 条路径）：
  - 先跑 128 帧让 cache 收敛，再平均 128 帧。不预热时间接光的蓝色通道低 15%：早期帧的 cache 还是空的；
  - 结果：各通道的总量差 3–4%；间接光（总量减去直接光）是参考的 90–95%，界限 85%–110%；剩下的偏暗来自 cache 的体素平均和更深的弹射；
  - 逐像素的平均误差 < 15%，因为 GPU 和参考都有噪声。

  marlin-material 的其他 ReSTIR 测试关掉 GI（它们对照的是直接光的参考）；改成 48 B 蓄水池以后都不变，golden 也不变。framework 的端到端测试也关掉 GI：它们要求 cookd 和包的第一帧逐像素相同，而两边加载的帧数不同，GI 的随机数和历史也就不同，和关掉 TSR 是同一个原因。resize 测试保留 GI。
- **开销**（1080p，`light_hall(1000)`，RTX 5060）：ReSTIR 从 3.0 ms 到 4.3 ms：
  - `RestirInitialGi` 0.80 ms；
  - `SharcUpdate` 0.29 ms，`SharcResolve` 0.04 ms；
  - `RestirSpatialShift` 多 0.35 ms，因为表面样本的可见性射线更长。

  PC 代理预算的测试在 R4f。

## 4. 世界 radiance cache

### 4.1 SHaRC 式哈希网格

- **键**：世界位置量化到体素，体素大小随到相机的距离按对数分级；再加上法线的粗略方向（6 个主轴方向之一），区分墙的两面。64 位键，开放寻址哈希表。
- **值**：累积的辐射亮度（RGB）、样本数、最后访问的帧号。
- **更新**（场景级，异步计算）：
  - 每帧按"cache 更新比例"抽一部分屏幕像素，从它们出发追踪多次弹射的路径（命中点用简化材质加 NEE，路径在远处查已有的 cache 项），把路径上每个顶点看到的辐射亮度原子累加进对应的项；
  - 一个 resolve pass 把累积量合并进项里，按时间衰减；
  - 很久没被访问的项被清除。
- **查询**：路径在 `x2`（或更深）终止时，查它所在体素的项；查不到就用天空环境光近似。
- 每个视图都从自己的像素里抽样，但所有视图共用一张表。
- 内存：每项约 40 B；2^20 项约 40 MiB。

### 4.2 NRC

- 一个很小的 MLP（例如 4 层 × 64 宽），输入是位置编码、法线、粗糙度、视向，输出辐射亮度。
- 每帧在线训练：训练样本来自 cache 更新路径的长尾部分。
- 推理和训练都用 cooperative vectors（SM 6.9），只在有矩阵单元的平台上启用：
  - NV 的 RTX 显卡、RDNA4、Arc；
  - PS5 Pro 和 NS2 的 tensor core，等平台 API 确认之后。
- 用 target 描述里的 capability 做开关（0005），不在 shader 里写平台分支。没有矩阵单元时退回 SHaRC。

### 4.3 R4b 的实现（2026-10-19）

`marlin_render::sharc`（`Sharc`）和 `Lighting/Sharc.mshader`。和 §4.1 的出入、定下的细节：

- **表**：容量是 2 的幂（默认 2^20，L1 的值；R4f 按档位设），每 16 项一个桶，桶内线性探测。每项存 64 位键的 32 位校验和（另一个哈希，0 表示空），插入是对桶内各项依次 `AtomicCompareExchange(0 → 校验和)`，查找扫描整个桶，所以删除项不会打断探测链。两个线程同时插入同一个键时按同样的顺序扫描，抢到的是同一个空位；删除留下的空位可能让同一个键出现两项，只是样本分开，和 SHaRC 一样。
- **键**：体素大小 = 2 的幂，约为到相机距离 × `voxel_angle`（默认 1/64），级别 l 对应 2^(l−16) m（15 µm 到 32 km，5 位）；坐标每轴 17 位；法线的主轴方向 3 位。级别跟随相机距离，相机移动后旧级别的项没人更新，按 `stale_frames`（64 帧）清掉。
- **每项 56 B**（不是 §4.1 估计的 40 B）：校验和 4 B、本帧的累加 32 B（R、G、B 和样本数，各 64 位）、平均后的辐射亮度和样本数 16 B、未更新的帧数 4 B。2^20 项 56 MiB。
- **累加用 64 位整数原子操作**（定点数，单位 2^−20 nit）：SHaRC 用 32 位，所以要先乘曝光；64 位不依赖曝光，也就不依赖哪个视图的自动曝光，阳光下的白墙一个样本约 3·10^10，能累加上亿个样本。代价是需要 `Features::atomic_int64`：支持光线查询的平台都有，没有的设备上 `RenderSide::sharc` 是 `None`。
- **更新**（`SharcUpdate`）：每 `stride`² 个像素（默认 4×4，L1 的 1/16）每帧随机挑一个，从它的 `x1`（深度和材质缓冲的 proxy lobe）出发，按余弦分布弹射，最多 `max_vertices` 个顶点（默认 4）。每个顶点：
  - 在自己的体素里插入项；
  - 做 NEE：太阳（一条阴影射线）加上一个局部光源：从随机一个 light tile 里抽 `candidates`（默认 16）个候选，按未遮挡的贡献做 RIS 留下一个（和 `RestirInitial` 一样），再打一条到它球面一点的阴影射线。最初的实现每个顶点只按功率抽一个光源：`samples/lights` 有上千个光源，抽到的大多照不到这里，每个体素只是少数几个光源的颜色，调试视图是一片彩色马赛克（用户 2026-10-19 发现）；改成 RIS 以后 1080p 下和正常着色的画面一致，只剩体素级的轻微噪声；
  - 天空不做 NEE：弹射射线没打中东西时看到的就是天空的亮度（余弦采样对均匀的天空是完美的重要性采样）；
  - 命中点用简化材质（0011 §9）和它的自发光。打到背面（闭合网格内部）时路径以 0 结束。

  从第二个命中点起，如果命中点的体素已经有 `terminate_samples`（16）个样本，路径就在那里结束，用 cache 的值；最后一个顶点的弹射也这样结束。这样光可以经过 cache 一帧帧继续弹射下去。路径结束后从后往前算每个顶点反射出去的辐射亮度（NEE + 反照率 × 下一个顶点的自发光和反射），加进各自的项。
- **resolve**（`SharcResolve`）：平均值最多保留 `max_frames`（默认 32）帧的样本，**按帧数而不是样本数限制**：历史权重取 `min(旧样本数, 本帧样本数 × (max_frames − 1))`。按样本数限制时，很少有路径到达的体素（远处、掠射角）每帧只拿到 1/65 的新值，收敛慢很多（测试里看到 96 帧后还低 10%）；SHaRC 也是按帧数。
- **只存反射光，按 Lambert 算**：不含自发光（命中点的简化材质有）和镜面反射，符合 §2.9 第 3 条，`I` 只读反射光。
- **查询**：`SharcQuery(sources, p, n)` 返回 rgb 和样本数（w 为 0 表示没有这一项）。查不到时怎么办由读的人决定（R4c）。
- **什么时候运行**：R4b 时没有 pass 读 cache，只在 `sharc_view` 打开时更新；R4c 起 GI 读它，`RenderSide` 在 `restir.gi` 开着时每帧更新。`r.sharc.view`（开发用 cvar）把每个像素换成它所在体素的辐射亮度，看起来就像 cache 照亮了场景。
- **测试**（`marlin-material/tests/gpu/sharc.rs`，测试里每个像素一条路径，体素更大）：
  - 内壁全是自发光材质（反照率 ρ、亮度 E）的封闭盒子：每个面反射 ρE/(1−ρ)，ρ 按 8 位平方根编码取值，200 帧后误差在 3% 内。它检查多次弹射、自发光、经过 cache 的反馈和 resolve。
  - 太阳和天空下的地面：ρ(E/π·cosθ + L)，误差在 2% 内。
  - `lit_wall` 预制场景（四个点光源）和 CPU 参考：参考值在每个体素的面上取 8×8 点平均。单个体素的误差在 15% 内（每个体素几百个样本，每个顶点一个 RIS 选出的光源；改成 RIS 之前最差的体素差 45%）。整面墙的总和误差在 3% 内，检查无偏。

### 5.3 太阳

**L0–L2：VSM，只用于方向光。**

- clipmap：每级的虚拟分辨率是 16K²，页大小 128²。
- **页标记**：从深度缓冲重建世界位置，标记需要的页（也包括半透明和体积雾请求的页）。
- **页分配**：从物理页池里分配。物理页池的大小按平台定，NS2 4K²，XSS 6K²，PS5/XSX/PC 8K²。
- **渲染**：用 cluster DAG 的可见性管线（0009 §4），按页的分辨率选 LOD，HW 和 SW 光栅写进页池。
- **缓存**：静态物体的页跨帧保留；动态实例的包围盒覆盖到的页，以及太阳方向变化时，相应的页失效。
- **过滤**：L0 用 PCF；L1–L2 用少量样本的 shadow map ray marching（SMRT 式）得到接触硬化的软阴影。
- 结果写成一张屏幕空间的太阳阴影遮罩。ReSTIR 的 target 和着色里，太阳作为一个"预先算好可见性"的光源处理：不参与重采样，直接加到最终着色上。

**L3 以上**：太阳进 ReSTIR，和其他光源一样。阴影射线在太阳的角直径内做锥形采样，得到软阴影。不分配 VSM。

- 云的阴影（0013 §2.4）在两条路径里都是一个乘子。

### 5.4 clustered 光源网格

- 一个视锥对齐的 3D 网格（例如 16×9×24），每个格子列出影响它的局部光源。
- 不透明物体的光照不用它，它是给这些路径用的：
  - 半透明（0009 §8）；
  - 体积雾（0013 §3）；
  - 粒子（0013 §8）；
  - 毛发（0013 §7）。
- 这些路径的阴影：太阳用 VSM 或 RT；局部光源 L2 以下不投影，L3 以上每像素打一条阴影射线，按重要性随机选一盏光。

### 5.5 R3b 的实现（2026-10-18）

物理单位、关卡里的光源组件和预采样 light tile。局部光源在 R3c 的 ReSTIR DI 之前还不参与着色。

- **环境**（`marlin_render::Environment`）：
  - 太阳的照度用 lux（`sun_illuminance`，默认 100 000，正午的直射阳光），颜色另外给（`light_color`）；
  - 环境光 `ambient` 是"四面八方亮度相同的天空"的亮度，单位 nit；背景 `clear_color` 也是 nit。
  - 着色时朝向太阳的 Lambert 表面反射 `albedo · E / π`，环境光贡献 `albedo · ambient`。
  - 默认的环境光和背景，是 R1 的相对值乘以 100 000/π。这样阳光、环境光、背景同比例放大，自动曝光之后画面不变（`sample_first_frame` 和材质的 golden 都没有变）。示例关卡的 `ClearColor` 按同样的比例换算。
  - 关卡的 `Environment` 多了 `SunIlluminance`。
- **曝光**：直方图的 log2 亮度范围从 −12..10 改成 −10..20（nit），覆盖到阳光照亮的雪地。原来的上限 1024 nit 在白天的场景里会饱和。
- **HDR 目标的范围**：`Rgba16Float` 最大 65 504。现在只有 Lambert 漫反射，最亮的是反照率 1 的表面在正午阳光下，约 31 831 nit。等有了镜面高光和太阳圆盘，就要做 pre-exposure（按上一帧的曝光缩放后再写 HDR，§8.1）。
- **材质测试**直接读光照结果、不经过曝光，所以用 R1 的相对值做环境（太阳 π lux，`E/π = 1`），参考图不变。
- **光源组件**（关卡格式）：
  - `PointLight { Color, Intensity, Radius, Range }`；
  - `SpotLight { Color, Intensity, Radius, Range, InnerAngle, OuterAngle }`，沿实体的 −Z 方向照射。
  - `Intensity` 是光通量（lm，60 W 灯泡约 800），换算成发光强度 `Φ/4π` cd。聚光灯也按点光源换算（UE 的做法），收窄锥角不会让它变亮。
  - `Radius` 是发光球体的半径（米），`Range` 是光衰减到 0 的距离（米）。
  - 字段缺省时是 0。0 没有意义的字段按约定取默认值，和 `Camera` 一样：黑色的 `Color` 当作白色，0 的 `Range` 当作 10 m，0 的 `OuterAngle` 当作 44°（UE 的默认值）。
  - 衰减曲线（加窗的平方反比）在 R3c 的着色里实现。
- **组件放在哪里**：
  - 光源组件和 `StaticMesh`、`Camera` 一样，是引擎组件，由渲染器消费，以后也不会变成脚本。
  - 现在它和其他引擎组件一起，临时放在 framework 的 `Component` 枚举里，生成和提取的代码在 `Engine` 里（`Light::from_component`、`Engine::extract_lights`）。等 VM 和 world/gameplay 框架定下对象模型（0018），引擎组件改成各自 crate 里通过反射注册的类型，这些代码搬出 framework。
  - 关卡的文本格式（`PointLight { … }` 块）不用变。会变成脚本的是 `Spin`、`FlyCamera` 这类组件。
- **提取**：ECS 里的 `Light` 组件；新增、`Light` 或 `Transform` 改变的实体整条发送（`LightUpdate::Add`/`Set`），组件被移除或实体被销毁时发送 `Remove`。`LightDesc` 多了 `radius`，放在 GPU 光源行的空位里（第 7 个字）。
- **light tile**（`marlin_render::lights`，0010 §2.8）：
  - 每帧 128 个 tile × 1024 个光源，从场景里的点光源和聚光灯中按功率（光通量 × 颜色的亮度）抽取，每条记录光源行号和它被抽中的概率。太阳不在里面（VSM）。
  - 抽样用别名表（Vose 方法），CPU 每帧从场景的光源重建，复杂度 O(光源数)，几千盏光源是微秒级。光源到几十万盏时，再换成 GPU 上建的功率金字塔。
  - GPU pass `PresampleLights` 用每帧不同的种子做哈希，抽取所有记录。
  - 现在每帧声明，但还没有 pass 读它，所以被 graph 剔除；R3c 开始读。
  - 记录里只有行号和概率，着色时再去光源表里读光源。RTXDI 把压缩后的光源数据直接放进 tile，缓存一致性更好；等 R3c 实测之后再决定要不要这样做。
- **测试**：
  - CPU：
    - 别名表给每盏光源的概率恰好等于它的功率占比（257 盏随机权重，误差小于 1e-6）；
    - 功率为 0、负数和 NaN 的光源从不被抽中；
    - 100 cd 的白光是 400π lm，方向光的功率为 0；
    - 提取：光源组件的换算（lm → cd、缺省值），生成、移动、调亮、销毁各发送一次，行号不变。
  - GPU：
    - 5 盏光源的抽中次数都在期望值的 5σ 以内，记录的概率正确，方向光和暗的光源从不出现；
    - 每个 tile 都抽到最亮的那盏；
    - 同一个种子结果相同，换种子结果不同；
    - 删除的光源下一帧离开 tile，没有光源时没有 tile。
  - 开窗口跑 `samples/basic` 12 秒，没有报错。

### 5.6 R3c1 的实现（2026-10-19）

ReSTIR DI 的第一步：初始采样、阴影射线和着色，还没有复用。R3c 拆成三步：R3c1、时域复用（R3c2）和配对空间复用（R3c3）。

- **pass**（`marlin_render::restir`，`Lighting/Restir.mshader`）：
  - `RestirInitial`：每个像素从一个 light tile 里抽 `candidates` 个光源（桌面默认 16，即 L2）。同一个 8×8 屏幕 tile 用同一个 light tile，每帧换。用 RIS 选一个：权重是 target / 源 pdf，target 是不带可见性的贡献的亮度。
  - `RestirShade`：向选中光源球面上朝向表面那一半的一个点打一条阴影射线（对 TLAS 做 ray query），把贡献 × `W` 加到 HDR 场景上。
- **蓄水池**：每个像素 32 字节（光源行号、球面采样点、`W`、`M`、target）。现在是瞬态 buffer，R3c2 变成历史资源。
- **着色**：和太阳一样是 Lambert，`albedo/π · I · cos θ / d²`，乘 UE 的距离窗 `saturate(1 − (d/range)⁴)²`，聚光灯再乘锥形衰减的平方。镜面在最终着色（§2.6）里加。
- **点光源和 BSDF 采样**：只有 `Dnee`。解析光源（点、球）不能被 BSDF 射线打到，所以不做 `Dhit` 和 MIS（Falcor 对解析光源也不做 MIS，§2.10）。自发光三角形和天空进来以后（§5.2）再加 `Dhit`。
- **framework**：`RenderSide` 在直接光照之后、后处理之前声明 ReSTIR。场景里有可抽的光源时才声明。
- **修掉的 bug**：材质 pass 用模型矩阵本身变换顶点法线。在非均匀缩放下法线会歪：缩放 (20, 20, 0.2) 的墙，法线变成 (0.097, 0.097, 0.990)。现在用逆转置（余子式矩阵乘以行列式的符号）。这个 bug 是 ReSTIR 测试对照 CPU 参考时发现的，单独提交，示例的参考图（地面）重新生成。
- **示例**：`samples/lights` 是单独编写的资产关卡：夜晚的大厅，有地面和柱子，1024 盏光源（点光源 200–2000 lm，每 8 盏中有一盏是朝下的聚光灯），没有太阳。没有复用和降噪时画面噪点很多：每个像素只有少数候选落在光源的 6 m 范围内。这正是 R3c2/R3c3 和降噪要解决的问题。光源多而分散时，light tile 之外还要不要加局部的光源网格（ReGIR，§14），等复用做完再看。
- **测试**（`marlin-material/tests/gpu/restir.rs`，场景来自 `marlin-test-scenes`，0014 §6.4）：
  - `lit_wall` 64 帧平均之后和 CPU 参考比：平均相对误差小于 3%，90% 的像素误差小于 10%；
  - Cornell box 128 帧平均之后：平均误差小于 5%，90% 小于 20%（球形光源的软阴影每帧只采一个点）；
  - Cornell box 的 golden image；
  - 开销和光源数无关：`light_hall` 在 640×360 下，ReSTIR 各 pass 的 GPU 时间，10 盏光源 0.117 ms、1000 盏 0.192 ms。多出来的部分来自更多像素找到了光源、要打阴影射线，不是因为光源多；断言 1000 盏不超过 10 盏的 1.5 倍加 0.05 ms。
  - 开窗口跑 `samples/lights` 12 秒，没有报错。

### 5.7 R3c2 的实现（2026-10-19）

时域复用（§2.4）。

- **初始样本的可见性**：`RestirInitial` 给选中的样本打一条阴影射线。被挡住的样本保留置信度 `M`，但权重清零，这样被挡住的光源不会通过复用扩散出去（RTXDI 的做法）。桌面默认开（`initial_visibility`）。最终着色时再测一次。
- **蓄水池带着自己的表面**：剩下的空位存像素的法线（八面体编码）和到相机的距离，下一帧用来判断是不是同一个表面。
- **`RestirTemporal`**：
  - 按运动向量找到上一帧的像素，取它的蓄水池（每个视图一个历史资源 `DiReservoirs`）；
  - 表面变了（到相机的距离差超过 10%，或法线夹角的余弦小于 0.9）就不用；
  - 上一帧样本的 target 在这一帧的表面上重新计算；
  - 置信度截到 cap，两个蓄水池按 `W · target · M` 做 RIS 合并，写进这一帧的历史。
  - 合并用置信度加权（1/M 式的 MIS），不是成对 MIS。场景静止时没有偏差；target 变化大时有偏差。成对 MIS 和 R3c3 的空间复用一起做。
- **cap 和 duplication map**（PTE §5，用户确认采用）：
  - `RestirDuplication` 在每帧最后算 duplication map：每个像素在 17×17 邻域里有多少个像素持有同一个初始样本（样本的身份是 `Hash(光源) ^ 球面随机数`，每个像素每帧都不同），除以 288。
  - 实现：16×16 的组把 32×32 的样本 id 读进 groupshared，再在里面数。
  - 下一帧的 cap 是 `lerp(20, 1, d^0.1)`。map 是每个视图一个持久 buffer，第一次用时清零。
  - 只有时域复用时几乎没有重复，它主要给 R3c3 的空间复用用。
- **光源变化**：
  - `RenderScene::light_changes` 记下上一次 apply 里新增、修改或删除的光源行，作为位集传给 `RestirTemporal`；上一帧的样本如果属于这些光源，就不用（它的权重是旧光源的）。不这样做的话，光源移动后的下一帧误差是 23%（置信度合并的偏差，要 20 帧才能淡出）；这样做之后和新场景的第一帧一样，是 16%（单帧噪声）。
  - 每帧都在动的光源因此没有时域复用：噪声大一些，但没有偏差和拖影。
  - 删除的光源，它在 GPU 上的行写成全 0（kind 0 不照亮局部），还引用它的蓄水池贡献为 0。
- **测试**（`marlin-material/tests/gpu/restir.rs`）：
  - 原来的收敛测试在开着时域复用时照样通过（静止场景）。
  - 噪声：256 盏光源的大厅，历史填满之后的单帧，和多帧平均的均方根误差从 5.15 降到 1.41（降到 0.27 倍，断言小于 0.5 倍）。
  - 移动和删除光源：移动后的下一帧误差和新场景的第一帧相同（0.1576 对 0.1576）；删除后的下一帧全黑。
  - 相机移动 0.5 m 后的下一帧，误差 0.035，新场景第一帧是 0.159（断言小于 0.6 倍）。如果运动向量用反了，复用到的是别的像素的历史，误差会比第一帧大。
  - Cornell box 的 golden 因为时域复用而改变，重新生成。
  - 开窗口跑 `samples/lights`：曝光正确，仍有彩色噪点，比 R3c1 少得多。

### 5.8 R3c3 的实现（2026-10-19）

配对空间复用（§2.5）。

- **配对图案是 cook 出来的资产**：
  - 运行时类型是 `marlin_render::asset::PairingPattern`，cooker 在新的 `marlin-cook-render` 里。
  - 引擎用的那份是 `content/engine/lighting/PairingPattern.masset`（`Marlin.Engine.Lighting.PairingPattern`，按名字找）：3 张图案，254²、230²、210²，半径 30。
  - cook 后的格式：每个像素一个 16 位偏移，`(dx + 128) | (dy + 128) << 8`。`RestirDi::new` 把它一次性传到 GPU 上。
- **生成方法**（PTE §3.1 的 2×2 洗牌）：
  - 开始时每个像素和横向的邻居配对。
  - 每一步随机选一种 2×2 网格的对齐方式，把每个 2×2 块里的 4 个像素随机打乱，配对关系跟着像素一起移动。
  - 每一步每个像素在每个轴上最多移动 1，所以偏移是随机游走，趋向正态分布；配对始终两两成对。
  - 均方偏移达到 2σ² 时停止，σ√(π/2) = 2r/3。
  - 偏移按未折回的整数记录，所以伙伴的偏移正好是相反数。这样到了屏幕上（屏幕不会折回）配对仍然互为伙伴，任何一边都不超过 8 位。
  - 测试（`marlin-cook-render/tests/unit/pairing.rs`）检查：
    - 每个像素都是它伙伴的伙伴；
    - r = 30 时平均距离和半径 30 的均匀圆盘相差不到 5%；
    - 落在 ±σ 内的比例约为 68%。
- **每帧的摆放**和 Falcor 的 `PairedNeighborTransform` 一样：所有图案共用一次随机平移，加上 x 翻转、y 翻转、转置三个随机位。屏幕偏移用摆放的逆变换算回来，所以变换之后配对关系不变（对 8 种翻转组合都在 CPU 上验证过）。
- **两个 pass**，在 `RestirTemporal` 和 `RestirShade` 之间：
  - `RestirSpatialShift`：每个像素把自己的样本移到每个伙伴那里，算出在伙伴表面上的 target，写进 `DiShifts`（每个邻居槽、每个像素一个 float）。
    - `spatial_visibility`（L2 以上，桌面默认开）时，从伙伴那里补一条阴影射线。
    - 伙伴在屏幕外，或者两边不是同一个表面（判据和时域一样，但做成对称的，两边结论一致），写 -1。
    - 一对像素之间的两次 shift 各只算一次，这就是配对的好处。
  - `RestirSpatial`：用按置信度加权的成对 MIS（Falcor 的 `SpatialResampling`，Lin et al. 2022）重采样自己的蓄水池和伙伴们的。
    - 所需的两个 target 都从 `DiShifts` 读：伙伴的样本在这里的 target 读伙伴的那一项，自己的样本在伙伴那里的 target 读自己的那一项。
    - 输出的置信度是所有参与者的和。下一帧时域复用时再截到 cap。
- **历史**：时域复用的结果写进临时 buffer，空间复用的结果才写进 `DiReservoirs`，所以下一帧的时域复用读到的是空间复用之后的蓄水池（PTE、RTXDI 的做法）。duplication map 也在空间复用之后的蓄水池上算：样本被邻居复制得越多，下一帧的 cap 越低。
- **设置**：
  - `spatial_neighbors`：默认 2（L2），最多为图案数；0 关掉空间复用。
  - `spatial_visibility`：默认开。
- **半径和分辨率**：
  - 半径按像素算。测试用的视图只有 96×64，30 像素差不多是半个画面，邻居在墙上离得很远。`lit_wall` 的光源离墙只有 0.3–0.9 m，target 在几个像素内就变化很大，移过来的样本权重波动很大，时域复用又把这些噪声带下去：64 帧平均的误差从只用时域复用的 0.026 升到 0.068。
  - 曾怀疑是 confidence cap 带来的偏差。逐项排查后排除了，原因是噪声，不是偏差：
    - 只开时域复用，64 帧平均的误差是 0.026，cap 在场；
    - 关掉 duplication map，误差仍是 0.070；
    - 把所有置信度都设成 1，误差仍是 0.055；
    - 画面总亮度是参考的 99.3%。
  - 半径 8 时误差是 0.025，半径 3 时是 0.013，比只用时域复用还低。
  - 引擎的 30 像素换算到 1080p，在 64 像素高的视图里约 2 像素，所以测试的 harness 用半径 3 的图案，让邻居在场景里的距离和真实屏幕上相当。引擎本身仍然是 30 像素。半径要不要随分辨率变，列在 §14。
- **测试**（`marlin-material/tests/gpu/restir.rs`）：
  - 原有的收敛、光源变化、相机移动测试都开着空间复用通过。
  - 相机移动后的误差是 0.046，新场景的第一帧是 0.108。
  - 新测试 `spatial_reuse_lowers_the_noise`：256 盏灯的大厅，只开空间复用（不开时域复用）的单帧均方根误差从 5.15 降到 4.45。
    - 一轮、两个伙伴，伙伴有一部分落在柱子上被拒绝，所以只降了七分之一左右。
    - 断言小于 0.9 倍。
  - 开销：640×360、10 盏灯时，ReSTIR 从 0.25 ms 升到 0.36 ms，包括每个邻居一条阴影射线。
  - Cornell box 的 golden 因为空间复用而改变，单独提交重新生成的图。

## 6. 降噪

自研，ReBLUR/ReLAX 那一类，漫反射和镜面两路分开。

### 6.1 通用：由产出者声明噪声统计（2026-10-19 用户确认）

传统的降噪器默认输入噪声每帧都是新的、彼此独立的白噪声。ReSTIR 的输出不满足这三条：

- **时域相关**：一个样本可以在历史里活很多帧。降噪器把每帧都当成一个新样本来累积，就会以为自己有 N 个独立样本，方差估得偏小，空间滤波偏弱，留下缓慢蠕动的斑块（boiling）。
- **空间相关**：空间复用把同一个样本复制到一片像素上，噪声是成片的低频斑块。3×3 的方差估计和小核 à-trous 会把这些斑块当成真实细节保留下来。
- **成团的萤火虫**：一个高权重的样本扩散到一片像素上，按单个像素抑制萤火虫的做法抓不到它。

但这些都是"噪声有多新、相关范围多大"的问题，不是 ReSTIR 专有的。所以只做**一个降噪器**，不做 ReSTIR 专用的，也不像 NRD 那样分成 ReLAX 和 ReBLUR 两套。它的输入契约多出两个可选的逐像素量，由产出这一路信号的算法填写：

| 量 | 含义 | 降噪器怎么用 | 普通蒙特卡洛 | ReSTIR |
|---|---|---|---|---|
| `Novelty`（0–1） | 这一帧的噪声里有多少是本帧新的；相邻两帧的噪声有 1 − `Novelty` 是同一份 | 历史仍然对各帧等权平均，但窗口拉长到 `MaxFrames / Novelty` 帧，使窗口里的独立样本仍是 `MaxFrames` 份；方差和模糊半径按"帧数 × `Novelty`"个独立样本计算 | 1 | 蓄水池记一个"新鲜置信度比例" f：初始采样为 1；时域合并时历史那部分算 0；时域和空间合并都按置信度 M 加权平均（不按 RIS 权重，见 §6.3） |
| `CorrelationRadius`（像素） | 噪声斑块的大小 | 方差估计、萤火虫抑制和历史夹取都用这个半径的邻域；空间滤波的半径不小于它 | 1 | 由 duplication map 换算：斑块面积约为 1 + 288·d 个像素，半径取 √(面积/π) |

- 新的噪声信号（RTAO、阴影、以后接进来的别的 GI 方案）只要如实填写这两个量就能接入，降噪器不用改。
- 去相关仍然是产出者自己的事：duplication map（§2.4）、每帧随机摆放的配对图案（§2.5），以后可能加 MCMC 变异。降噪器只负责知道输入是相关的，不被它骗。
- 信号的变化（光源变了、遮挡物移动了）不靠 `Novelty` 通知，由快历史和历史夹取兜住（§6.2）。
- 证明通用性的测试是合成信号：独立白噪声（`Novelty` = 1）和"同一份噪声持续 k 帧"（`Novelty` = 1/k），两者都应该降到同样干净。
- 没有噪声的信号不进降噪器，例如 VSM 照亮的太阳。

R3d 先做漫反射这一路；镜面等最终着色有了镜面（§2.6）再接，但接口一开始就按两路设计。

### 6.2 算法

`marlin_render::denoise::Denoiser`，shader 在 `Lighting/Denoise.mshader`（文件注释里有逐 pass 的说明）。

- **输入**（`NoisySignal`）：
  - `light`（`Rgba16Float`）：解调后的光（除以了反照率），alpha 是到光源的距离（hit distance，0 表示未知）；
  - `hints`（`Rg16Float`）：`Novelty`、`CorrelationRadius`；
  - 引导：材质缓冲（法线、反照率）、深度、运动向量。
- **`DenoiseTemporal`**：
  - 萤火虫：信号亮度超过邻域均值 + 4σ 的部分截掉。邻域是相关半径内同一表面上的 12 个点，按两圈排布，每帧转一点。
  - 重投影：按运动向量找上一帧，双线性取 4 个点，每个点都要通过同一表面的检验（到相机的距离差 10%、法线夹角余弦 0.9）。
  - 慢历史：对各帧等权平均，窗口最多 `MaxFrames / Novelty` 帧（默认 `MaxFrames` = 32）。存成 `Rgba32Float`：窗口可以长到几千帧，半精度的平均会停在离均值还差一截的地方。
  - 快历史：最近 4 帧的平均，用来察觉变化。
- **`DenoiseClamp`**：
  - 把慢历史的亮度夹在 [像素自己的快历史 ± 1.5 σ] 里，σ 是快历史在相关半径内邻域的标准差；
  - 夹掉多少，慢历史的帧数就按比例减少多少（anti-lag）；
  - 写出这一帧的历史，和"信号方差 / 独立帧数"作为空间滤波的方差。
- **`DenoiseBlur`，两遍**（第二遍半径减半）：
  - 16 点泊松盘，每个像素、每帧随机旋转；
  - 半径 = max(32 像素 × 高度/1080, 相关半径) / √(1 + 独立帧数) × saturate(相对误差 / 0.1)（§11.2），并且不超过 hit distance 在屏幕上的投影（光源离表面越近，阴影越锐利）；
  - 边缘停止：到中心平面的距离（2% 视距）、法线（16 次方）、亮度（4 倍标准差）。
- **`DenoiseCompose`**：乘回反照率，加到 HDR 场景上。没有降噪的信号也用它合成。
- 去遮挡的像素没有历史，独立帧数从 `Novelty` 开始，所以模糊半径最大，这就是"去遮挡修复"。低 mip 的历史以后再加。
- 输出是降噪后的解调信号，交给合成（0011 §5.6）。蓄水池分辨率低于全分辨率的档位，降噪在全分辨率上做，因为着色已经是全分辨率的（§2.6）。
- 镜面一路以后接，用 hit distance 和粗糙度推出的虚拟运动重投影。

### 6.3 R3d 的实现（2026-10-19）

- **接入**：
  - `RestirDi::add_passes` 不再直接加到场景上，而是返回 `NoisySignal`：`RestirShade` 写出解调后的光和 hit distance，以及提示。`Novelty` 是蓄水池的 `Fresh`（原来空着的那个字），`CorrelationRadius` 由这一帧的 duplication map 换算，所以 `RestirDuplication` 挪到了着色之前。
  - `RenderSide` 有 `denoiser` 和 `denoise`（默认开）；关掉时把原始信号直接合成。
  - 材质测试的 harness 默认不降噪，所以 ReSTIR 自己的收敛测试照旧测原始信号。
- **调试中发现的几个问题，都记成了设计规则**：
  - **`Novelty` 不能和信号的值相关。** 最初按 RIS 权重算新鲜比例，这恰好是"着色样本是本帧新抽的"的概率，但它跟样本的值相关，用它加权的平均就有偏差。改成按置信度 M 加权。
  - **`Novelty` 描述的是相关性，不是混合权重。** 最初把它当混合权重（α = Novelty/帧数，帧数每帧加 Novelty）。ReSTIR 的 Novelty 约 0.05，64 帧后"帧数"才 4，第一帧的噪声还占 1/4 的权重，而后面那些更好的帧每帧只占 0.05。正确的模型是：对相关的样本，最优平均仍然对各帧等权，相关性只是让同样多的独立样本要更多帧才凑得齐。所以权重按真实帧数，窗口按 `MaxFrames / Novelty` 加长。改完之后，`lit_wall` 收敛时的误差从 0.044 降到 0.021（只看时域、不开空间滤波时）。
  - **慢历史要用 32 位浮点**（见 §6.2）。
  - **夹取以像素自己的快历史为中心，不以邻域均值为中心。** 邻域均值在尖锐的亮峰处总是比峰值低（Cornell box 天花板上紧贴光源的地方），收敛之后带宽很窄，峰就被一直往下拉。σ 用邻域的，这样遇到特征（梯度带来的离散）带宽自然变宽。
  - **夹取带宽是取舍。** k = 1、1.5、2 时：
    - 新鲜噪声的稳态误差分别是 0.087、0.061、0.051；
    - 光源亮度变为 3 倍后 16 帧的误差分别是 0.093、0.115、0.163。
    - 取 1.5。
  - **快历史 4 帧**（ReLAX 的默认是 2）：试过 2，并没有更好。
- **测试**（`marlin-material/tests/gpu/denoise.rs`）：
  - 合成信号，每帧在平墙上喂已知统计的噪声。下面是第 256 帧的均方根误差：
    - 新鲜噪声（`Novelty` = 1）：0.061；
    - 持续 8 帧并如实声明（`Novelty` = 1/8）：0.128。256 帧里只有 32 份独立的噪声，只做时域平均的极限是 0.102；
    - 同样的噪声谎称是新鲜的（传统降噪器的假设）：0.181。
    - 断言：如实声明的不超过极限的 1.4 倍，谎称的比如实声明的至少差 30%。这证明降噪器对相关输入是通用的。
  - 变化跟得上：光源亮度变为 3 倍。新鲜噪声 16 帧后误差 0.115；持续噪声 32 帧后 0.211（受新的噪声出现的速度限制）。
  - ReSTIR + 降噪，对照 CPU 参考：
    - 256 盏灯的大厅第 64 帧，误差从 0.341 降到 0.116，第 90 百分位从 0.665 降到 0.256；彩色光源下 RGB 各通道的能量和参考相差不到 3%。
    - 收敛后（第 256 帧）：Cornell box 0.017，能量 0.992；`lit_wall` 0.010。剩下的是模糊在尖锐光源处的偏差。
    - 相机移动 0.3 m 后的第一帧误差 0.214，移动后视图自己的第 64 帧是 0.182。历史通过运动向量找到了。
  - golden `cornell_box_denoised`。
  - 开销：640×360 下 0.25 ms（RTX 5060），1080p 约 2.2 ms，比 ReLAX 的 1–1.5 ms 重。以后的优化：半分辨率的方差和预模糊、用 groupshared 读邻域。
- **samples/lights**：开窗口运行正常。离线渲染 1280×720、300 帧：
  - 降噪后噪点基本消失，只剩柔和的低频斑块。
  - 原始画面偏绿，降噪后接近粉白。这是因为色调映射是非线性的：先平均再映射，和先映射再平均不一样。原始画面每个像素只显示一盏灯的颜色，而且很亮。harness 里逐通道对照参考，降噪后的颜色是对的。

**DLSS Ray Reconstruction**（NV 上可选）：`Upscaler::caps().denoises` 为真时，graph 不声明降噪器和 TSR，直接把带噪声的漫反射、镜面和引导信息（反照率、法线、粗糙度、镜面 hit distance、运动、深度）交给它。

## 7. 超分、抗锯齿、帧生成

### 7.1 TSR

自研的时域超分，是全平台的基线：

- **输入**：内部分辨率的颜色（已合成半透明）、深度、运动向量、reactive mask（0009 §8）、曝光。
- **抖动**：Halton(2,3)，相位数随超分倍率变化（8–32）。
- **历史**：保存在显示分辨率上，是视图的历史资源。
- **重投影和校正**：在 YCoCg 空间里按方差裁剪；细线和高光的闪烁用亮度历史抑制。
- **锐化**：可选，在输出前做一次自适应锐化。
- 动态分辨率下内部分辨率每帧都可能变，TSR 在每帧的抖动和缩放里处理这一点，历史不需要重建。

### 7.2 `Upscaler` trait

```rust
pub trait Upscaler: Send + Sync {
    fn caps(&self) -> UpscalerCaps;     // 支持的倍率、是否自带降噪（RR）、要不要 reactive mask
    fn render_size(&self, display: UVec2, mode: UpscaleMode) -> UVec2;
    fn jitter(&self, frame: u64, render: UVec2, display: UVec2) -> Vec2;
    fn add_passes<'g>(&self, g: &mut RenderGraph<'g>, view: ViewId, inputs: &UpscaleInputs<'g>)
        -> TextureHandle<'g>;
}
```

| 实现 | 平台 | 位置 |
|---|---|---|
| TSR | 全部 | `marlin-render` |
| DLSS SR / RR | PC（NV）、NS2 | PC：`render_ext/dlss`（cargo feature）；NS2：`platforms/switch2` |
| FSR 4 | PC（RDNA4） | `render_ext/fsr` |
| XeSS | PC（Arc） | `render_ext/xess` |
| PSSR 2 | PS5 Pro | `platforms/ps5` |

- 厂商 SDK 要直接拿到原生的 command list 和资源。graph 需要一种"外部" pass：声明读写和要求的状态，执行闭包里通过 `ctx.native()` 拿到原生句柄（0007 要补，§14）。
- 厂商 SDK 都是 C 接口的动态库或静态库，从 no_std 的 runtime 里通过 FFI 调用。

### 7.3 动态分辨率与帧生成

- **动态分辨率**：一个 PI 控制器以上一帧可用的 GPU 计时为输入，按视图调整内部分辨率的缩放。历史资源按最大内部分辨率分配，缩放只改视口，不重建资源。
- **帧生成**：只在 PC 上做，用 DLSS FG 或 FSR FG。它接在 present 路径上，和延迟手段（0008 §3.4）一起配置。接口形状待定（§14）。

### 7.4 R3e 的实现（2026-10-19）

用户确认的两点：桌面默认按原生分辨率渲染，TSR 只做抗锯齿，超分倍率作为设置提供；动态分辨率（§7.3）以后单独做。

- **抖动进相机**：
  - `Camera` 多了 `jitter`（这一帧的子像素偏移，单位是渲染像素）。
  - `marlin_render::view_projection` 是唯一构造视图矩阵的地方，在裁剪空间里平移 `2·jitter/尺寸`。可见性、材质、ReSTIR、降噪、VSM 都改成调用它，所以绘制和由深度重建世界坐标用的是同一个抖动。
  - 运动向量不含抖动：材质 pass 用不带抖动的上一帧矩阵，并从当前像素的 NDC 里减去这一帧的抖动。
  - ReSTIR 和降噪器按运动向量找上一帧的像素时，没有补上两帧抖动之差（最多一个像素）。它们本来就容忍几个像素的误差，以后需要再补。
- **`marlin_render::upscale`**：
  - `Upscaler` trait（§7.2；尺寸用 `UVec2`，抖动用 `Vec2`）；
  - `UpscaleMode`：Native、Quality（1.5×）、Balanced（1.7×）、Performance（2×）、UltraPerformance（3×），以及任意倍率；
  - `Tsr` 是第一个实现。
  - 抖动用 Halton(2,3)，相位数 `clamp(round(8·r²), 8, 32)`。
- **`TsrResolve`**（`Post/Tsr.mshader`），每个显示像素一个线程：
  1. 重建当前帧：周围 3×3 个渲染像素，权重是 `exp(−6·d²)`，d 以**显示像素**为单位，是样本落点（随抖动移动）到显示像素中心的距离，再乘 Karis 权重 `1/(1 + 曝光后亮度)`。这一帧对这个像素的话语权是核权重之和（上限 1），所以超分时离样本远的显示像素主要靠历史。
  2. 运动取 3×3 里最近的表面（反向 Z 最大）的，边缘跟着前景动。
  3. 历史用 5 次采样的 Catmull-Rom 取，在 YCoCg 里裁剪到"邻域均值 ± 1.25σ"，裁掉多少，历史权重就降多少。
  4. 混合：历史权重上限是 `16·r²`（最多 64），并随运动速度下降：`16 / (1 + 2·每帧移动的显示像素数)`。
  5. 曝光用上一帧的：后处理新增 `PostProcess::exposure`，在链路之前声明这个持久 buffer，TSR 读上一帧的值，后处理写这一帧的。
- **`RenderSide`**：
  - 有 `tsr` 和 `upscale: Option<UpscaleMode>`（默认 `Some(Native)`，`None` 关掉）；
  - 每帧先定渲染尺寸和抖动，再按渲染尺寸画整个视图，然后 TSR 到目标尺寸，后处理在显示尺寸上做。
- **SMRT 噪声按帧变化**（0009 R2h 留下的）：`VsmConstants::NoiseFrame` 由这一帧的抖动换算，交错梯度噪声每帧偏移 5.588238 像素。没有 TSR 时抖动为 0，噪声和以前一样不变，原有阴影测试不受影响。
- **调参中发现的问题**：
  - 一开始的重建核是 `exp(−2.29·d²)`（Blackman-Harris 的近似，σ ≈ 0.47 像素），按渲染像素计。和"64 帧抖动平均"（等价于按像素的盒子滤波）相比，误差 0.0038，没开抗锯齿是 0.0050。放开裁剪也只有 0.0037，所以问题不在裁剪，而在核太宽。
  - 核改为按显示像素计，锐度 6：
    - 原生 0.0020；
    - 2× 超分从 0.0111 降到 0.0046。
    - 4 和 10 都不如 6。
  - 平移时（每帧 0.4 像素），误差从静止的 0.0022 升到 0.0046。逐步放慢移动速度，误差会回到 0.0024，说明重投影是对的。剩下的是每帧按小数偏移重采样历史造成的软化，所以加了随速度下降的权重上限：系数 0、1、3 时误差分别是 0.0046、0.0044、0.0040，取 2。
- **测试**（`marlin-material/tests/gpu/tsr.rs`，新的预制场景 `marlin_test_scenes::scenes::edges`：阳光下的细条、方块和阴影）。对照把同一视图按 4 倍尺寸渲染、再按 4×4 盒子缩小得到的超采样参考，误差是按显示压缩（`c/(1+c)`）后的平均差：
  - 原生：TSR 0.0022，不开抗锯齿 0.0048（断言小于 0.6 倍）。
  - 超分，对比把小图双线性拉伸（断言小于 0.7 倍）：
    - Quality（86×54）：TSR 0.0038，双线性 0.0074；
    - Performance（64×40）：TSR 0.0045，双线性 0.0130。
  - 平移 32 帧之后：TSR 0.0042，同一视图不开抗锯齿是 0.0049（断言小于 0.95 倍；如果重投影错了，画面会拖影）。
  - 抖动：在像素内、均值接近 0、四个象限的覆盖大致均等、按相位数循环。
  - golden `edges_tsr_performance`。
  - 开销：输出 1080p 时 0.17 ms（RTX 5060），原生和从一半分辨率超分都一样。断言小于 0.5 ms。
  - 框架的端到端测试会比较不同运行之间的画面，而这些运行加载完成所用的帧数不同，TSR 的历史和抖动相位都随帧数变，所以这些测试关掉 TSR（`upscale = None`）。缩放窗口的测试保留 TSR，覆盖这条路径。
- **样例**：`samples/basic` 和 `samples/lights` 开窗口运行正常。离线渲染 1280×720、240 帧：
  - 原生 TSR 的边缘平滑，旋转的方块没有拖影；
  - 2× 超分明显更软，但同样没有拖影。
- **还没做**：
  - reactive mask（要等半透明，0009 §8）；
  - 锐化；
  - 亮度历史抗闪烁；
  - 去遮挡专门的处理：现在靠裁剪；
  - 镜头切换时清空历史：graph 有 `invalidate_history`，相机切换的信号还没接；
  - ReSTIR 和降噪器补上抖动之差；
  - 动态分辨率（§7.3）。

## 8. 后处理与显示变换

### 8.1 曝光

- 物理相机：ISO、快门、光圈，换算成 EV100；DOF 和运动模糊用同一组参数。
- 自动曝光：在异步计算上算亮度直方图，按测光模式加权，时间上平滑；可以被手动 EV100 和补偿覆盖。
- 曝光在超分之前乘进颜色（预曝光），超分和 DLSS 都需要这样的输入。

### 8.2 后处理链

```
超分输出 ─▶ DOF（scatter-as-gather，物理 CoC）─▶ 运动模糊（tile 最大速度）─▶ bloom
        ─▶ [PostProcess 材质：BeforeDisplay] ─▶ 显示变换（含调色 LUT）
        ─▶ [PostProcess 材质：AfterDisplay] ─▶ 胶片颗粒、暗角 ─▶ ViewOutput
```

- DOF 和运动模糊放在超分之后，在显示分辨率上做，这也是 DLSS 推荐的顺序。
- bloom：降采样和升采样链（0007 §11.2 的验收链）；Ultra 以上可以选 FFT 卷积 bloom，支持任意的光晕形状。
- 后处理材质的注入点见 0011 §10.2。

### 8.3 显示变换（可编程）

```csharp
public interface IDisplayTransform
{
    // 输入：已乘曝光的场景线性 Rec.709；输出：目标显示空间里的线性值（编码之前）
    float3 Apply(float3 sceneLinear, in DisplayParams d);

    // true：烘成 3D LUT；false：逐像素求值（需要做局部色调映射这类空间相关的操作时）
    const bool BakeToLut = true;
}

public struct DisplayParams
{
    public DisplayEncoding Encoding;   // Srgb / Pq / ScRgb
    public ColorGamut Gamut;           // Rec709 / P3 / Rec2020
    public float PeakNits, MinNits, PaperWhiteNits;
}
```

- 显示变换是一个**可编程的接口**，归在 PostProcess 材质域（0011 §10.2）。项目可以提供自己的实现（AgX、GT7 式，或者完全自定义的），不需要改引擎。
- 引擎自带两个实现：
  - `Aces2`：ACES 2.0 的输出变换，按峰值亮度参数化，同一张画面输出 SDR、HDR10 和 scRGB，带色域压缩。这是默认实现。
  - `Neutral`：一个色相稳定的中性 look（PBR Neutral 那一类），给产品展示、材质预览用。
- **LUT 烘焙**：`BakeToLut` 为真时，`Apply` 只在一张 65³ 的 3D LUT（输入在 log2 空间）上运行，调色 LUT 也合并进去；参数不变就不重烘。逐像素的成本只是一次 3D 纹理采样。
- 输出编码（sRGB 曲线、PQ、scRGB 线性）由引擎在最后一步统一做，`Apply` 只输出线性值。
- 调色的 LUT 由美术在外部工具里制作，作为 3D 纹理资产导入。
- 具体的语法形状（接口名、`const bool` 静态参数的写法）沿用 0004 §13.3，接口名要和 0011 的材质域一起确认（§14）。

## 9. 色彩

- 工作空间是**线性 Rec.709**。颜色纹理按 sRGB 制作，采样时由硬件转成线性。
- 光源颜色可以给色温（K），在 CPU 端换算成 Rec.709。
- HDR 输出的参数（峰值亮度、paper white、色域）来自平台的显示查询，或者玩家的 HDR 校准界面，作为 `DisplayParams` 传给显示变换。
- UI 在显示变换之后合成，在 sRGB 编码空间里混合（0012 §8）。

## 10. 异步计算编排

可以和光栅重叠、标成 `b.async_compute()` 的 pass：

| pass | 和什么重叠 |
|---|---|
| BLAS refit / 构建、TLAS 构建 | 可见性管线（visbuffer 光栅） |
| radiance cache 更新 | 可见性管线、材质解算 |
| light tile 预采样、自发光三角形收集 | 可见性管线 |
| 天空 LUT、云的天气图（0013） | 整帧前半段 |
| 曝光直方图 | 上一帧后处理的尾部 / 本帧开头 |
| VSM 页标记之后的静态页检查 | 材质解算 |

graph 会把异步 pass 提前到依赖允许的最早位置（0007 §4.3）。

### 11.1 1080p 实测和第一轮优化（2026-10-19，RTX 5060）

用户反馈 1080p 下整套只有 60fps，于是测量各 pass 的 GPU 时间。测法：离屏渲染 1920×1080，跑 250 帧进入稳态后取中位数。`Offscreen::gpu_timings` 是为此新增的。

| | 优化前 | 优化后 |
|---|---|---|
| `samples/basic` 全部 GPU pass | 3.4 ms | 1.5 ms |
| `samples/lights` 全部 GPU pass | 9.8 ms | 6.9 ms |
| VsmMask（SMRT） | 2.1–2.4 | 0.44–0.74 |
| 降噪的第二遍模糊 | 1.37 | 0.22 |
| RestirDuplication | 0.44 | 0.22 |
| 亮度直方图（lights） | 0.36 | 0.10 |

- **SMRT 自适应射线数**（UE 的做法）：先打最外圈的两条射线，两条结论一致（都照亮或都被挡）就说明像素不在任何半影里，直接返回。绝大多数像素属于这种情况。CPU 参考对照的阴影测试照旧通过；阴影边缘少数像素会变，相关 golden 重新生成。
- **降噪的模糊**：
  - 时域 pass 顺手写出相对相机的位置。模糊的每个采样点改为读位置和法线两张纹理，不再从深度和材质缓冲重建。
  - 第二遍只用 8 个采样点。
  - 同时修了一个 bug：第一遍输出的已经是"独立帧数"，第二遍又乘了一次 Novelty，导致第二遍的半径偏大。
- **duplication map**：17×17 窗口隔一个像素取一个（9×9），估计的是同一个比例，计算量是原来的四分之一。
- **亮度直方图**：先在 groupshared 里按工作组统计，每个 bin 再做一次全局原子加，代替每个像素一次全局原子加。为此编译器实现了 groupshared 数组上的原子方法（0004 §12.2）。
  - 中间试过按 wave 合并相同的 bin：lights 上是 0.12 ms，但循环次数取决于一个 wave 里有几个不同的 bin。
  - groupshared 版本是 0.10 ms，和画面内容无关。
- **没有改的**：
  - RestirInitial（1.4–1.7 ms）的开销和候选数成正比。8 个候选能省约 0.8 ms，但降噪后的误差会上升约 30%（大厅 0.119 → 0.154），所以保持 16 个。
  - 把光源数据压缩后存进 light tile 也考虑过，但 1024 盏灯的光源表只有 64 KB，本来就在缓存里，收益不确定，没有做。
- **CPU**：`cargo run` 默认是 debug 构建，每帧的 CPU 开销（场景、graph、录制）有十几毫秒，比 GPU 还大。看帧率要用 `--profile development` 或 release。CPU 端的优化另做。

### 11.2 2560×1369 的第二轮（2026-10-19）

用户的窗口是 2560×1369（像素数是 1080p 的 1.69 倍）。叠加层显示 68fps，`GPU` 14.76 ms，基本等于 `Frame`，所以瓶颈在 GPU。`CPU render` 13.79 ms 主要是在等 GPU，`CPU simulate` 只有 0.03 ms。

| `samples/lights`，2560×1369 | 第一轮之后（用户截图） | 第二轮之后 |
|---|---|---|
| 全部 GPU pass | 14.8 ms | 9.7 ms |
| RestirInitial | 3.88 | 1.26 |
| ReSTIR 全部（1024 盏灯的大厅） | 6.6 | 3.8 |

- **初始可见性拆成单独的 pass**（`RestirInitialVisibility`）：
  - 射线查询放在 RestirInitial 里，就算不执行也会在整个候选循环期间占着寄存器，占用率因此下降。
  - 16 个候选：带射线查询代码时 3.6 ms，去掉后 2.5 ms；拆开后两个 pass 加起来 2.3 ms，画面完全不变。
  - 同样的问题在 RestirSpatialShift 和 RestirShade 里不存在：它们的射线是主要工作，前面没有长循环。
  - 1 个候选也要约 1.1 ms 的固定开销，比按带宽估算的高。没有 GPU profiler，原因还没查清（§14）。
- **半分辨率棋盘格蓄水池**（§3 的 L2，默认开，`RestirDi::checkerboard`）：
  - 蓄水池是一张半宽的网格，单元 (i, y) 对应像素 (2i + ((y + 奇偶) & 1), y)。所有蓄水池 pass（初始采样、可见性、时域、配对空间复用、duplication map）都在单元上运行，配对图案也放在单元坐标上。
  - 着色在每个像素上运行。有单元的像素用自己的蓄水池；没有的像素，上下左右四个邻居正好都有，就在同一表面上的邻居样本里用自己的目标函数做一次 RIS 选样（§2.6 的蓄水池上采样），每个邻居等权。一个也不在同一表面时，用全部邻居。
  - 也试过 Talbot 的 1/|Z|（一个样本的权重是 1 除以"它的光照得到的邻居个数"）。在测试里测不出差别，每帧却多 0.6 ms，没有采用。
  - **奇偶固定，不交替**：
    - 交替时，同一个像素上一帧是另一种奇偶，时域复用永远从相邻像素取历史，按置信度合并在两个不同的表面之间就有偏差。`lit_wall` 降噪后的误差因此从 0.019 升到 0.063。
    - 交替的好处是两帧覆盖全部像素，这只在只着色一半像素的方案里才必要。我们每个像素都着色，用不着。
  - 代价：大厅降噪后的误差从 0.127 升到 0.153，第 90 百分位从 0.278 升到 0.339；`lit_wall` 从 0.019 升到 0.021；Cornell box 几乎不变。
  - 收益：2K 下 ReSTIR 从 6.6 ms 降到 3.8 ms。
- **有偏空间复用**（用户提出的，Bitterli et al. 2020 的 biased 版本；`RestirDi::biased_spatial`，默认关）：
  - 做法：邻居样本在本像素求目标，按置信度（1/M）合并，没有成对 MIS，没有 shift pass，邻居样本也不打射线。
  - 实测（大厅，第 64 帧）：

    | | 原始误差 | 降噪后误差 | 能量 | 2K 下 ReSTIR |
    |---|---|---|---|---|
    | 成对 MIS 加射线（默认） | 0.317 | 0.153 | 0.99 | 3.83 ms |
    | 成对 MIS，不打射线 | 0.346 | 0.162 | 0.97 | 3.83 ms |
    | 有偏 | 0.443 | 0.329 | 0.75 | 3.54 ms |

  - 柱子多的场景里，邻居样本不测可见性就常常选中被挡住的灯，着色射线一挡，像素就黑了，所以画面暗了 25%。只省 0.3 ms，不值得作为默认；留给低档位以后用。
- **默认分辨率**：仍然是原生。按帧率目标调整内部分辨率是动态分辨率（§7.3）的事，比按显示分辨率写死一个超分倍率合适。
- **降噪的模糊半径也看测得的误差**：原来的半径只随独立样本数缩小，ReSTIR 的 `Novelty` 低，要很久才缩小，可它的输出每帧其实已经比较准。现在半径再乘 saturate(相对误差 / `target_error`)，相对误差 = √方差 / 亮度，`target_error` 默认 0.1。
  - 480×272 下对照参考：大厅的误差从 0.0709 升到 0.0755；`lit_wall` 从 0.0081 降到 0.0072，渐变处不再过度模糊。
  - 2K 下两遍模糊从 3.2 ms 降到 1.2 ms（测试场景）；lights 样例的第一遍从 1.49 ms 降到 1.12 ms，整帧 GPU 是 9.25 ms。
  - 96×64 的测试分辨率下模糊半径本来就只有约 2 像素，看不出这项改动，所以画质要在更高的分辨率下对照参考来测。

## 12. 参考路径追踪器

- editor 里的一个视图调试模式：无偏、多次弹射，命中点一律用波前式完整材质，每帧 1 spp，相机静止时累积。
- 和 L4 用同一套 BSDF、TLAS 和材质解算代码，只是没有任何复用和缓存。
- 用途：
  - 给各档位的实时结果提供 ground truth；
  - 测试里做数值对比（§13）；
  - 美术用它校对材质。

## 13. 测试

- **平台无关**：
  - 配对纹理：每个像素的配对是互逆的（A↔B），偏移的分布接近目标 σ，可以平铺；
  - duplication map 的统计和 cap 公式；
  - 光源单位换算、色温换算、EV100；
  - ACES 2.0 实现和官方参考值对比（CPU 上逐点比较）；
  - TSR 的抖动序列和缩放。
- **平台相关**（真实硬件）：
  - **无偏性**：关掉去相关后，L2/L3/L4 累积足够多帧的结果和参考路径追踪器的结果做 FLIP/MSE 比较，误差在阈值内；
  - proxy target 和精确 target 收敛到同一个结果（只有噪声不同）；
  - 降噪器：静态场景累积若干帧后，和参考结果的误差有上界；
  - 显示变换烘焙成 LUT 和逐像素求值的结果一致（量化误差之内）；
  - 镜面追踪和 ReSTIR 的 lobe 划分不重复计数：粗糙度跨过 τ 时亮度连续。

## 14. 待定

- §3 和 §11 的数值要在主机上实测之后再调：
  - L0/L1 能不能在 NS2 上撑住；
  - PS5 的 60fps 预设具体降哪一项。
- NEE 候选数随深度递减的公式：`32/2^b`（PTE 正文）还是 `32/v²`（Falcor 代码），实测后定（§2.10）。
- 外部 GI 方案（探针、屏幕空间、烘焙）接进来时，它返回"只含反射光"的约定（§2.9 第 3 条）怎么落到具体方案上。
- ReGIR（世界网格的光源蓄水池）作为 light tile 的补充，在光源极多的场景里是否需要。
- 降噪器的优化（§6.3、§11.2）：半分辨率的方差和预模糊；用 groupshared 读邻域；去遮挡时用低 mip 的历史。
- 降噪器在蓝色通道上偏暗 2–4%（彩色光源的大厅，§6.3 的逐通道测试），原因待查。
- GI 在大部分被遮挡的凹处成块（`samples/basic` 圆环内侧、球的底部）：那里大多数样本是 0，复用把少数亮的样本扩散成岛，降噪器抹不掉。只看初始样本时是细碎的噪点，方向（R4c 之后）：每像素多几个 GI 候选、GI 样本的历史上限降低、或让 `CorrelationRadius` 反映这种扩散。cache 视图在那里同样暗，所以是噪声，不是偏差。
- RestirInitial 每个蓄水池约 1.1 ms 的固定开销（2K），比按带宽估算的高，要用 GPU profiler 看（§11.2）。
- 配对图案的半径随分辨率变不变（§5.8）：现在固定 30 像素（PTE、Falcor 的默认）；动态分辨率或很低的内部分辨率下，邻居在场景里离得更远。可以在图案资产里多存几档半径，按内部分辨率挑一档。
- NRC 在 PS5 Pro 和 NS2 上的可用性，取决于平台 API。
- graph 的"外部" pass（§7.2）：0007 要补这个 pass 类型。
- 帧生成的接口形状。
- 体积雾里要不要也用 ReSTIR（现在是 clustered 光源加 RIS，0013 §3）。
- `IDisplayTransform`、`DisplayParams` 的名字和形状要和 shader 语言的约定一起确认（0004 的规则：语言相关的命名先问再定）。
