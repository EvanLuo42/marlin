## 1. 天空与大气

### 1.1 模型

- 行星尺度：地面半径、大气厚度；Rayleigh、Mie 和臭氧吸收的参数，都在 `Environment` 表里（0009 §1.1）。
- 太阳和月亮是方向光（0010 §5.3），带角直径；它们的颜色由大气透射算出，不需要美术单独调。

### 1.2 LUT

| LUT | 尺寸（参考） | 更新 |
|---|---|---|
| 透射 | 256×64 | 大气参数变化时 |
| 多次散射 | 32×32 | 大气参数变化时 |
| 天空视图 | 192×108 | 每帧（场景级，异步计算） |
| 空气透视 | 32×32×32 froxel | 每帧、每个视图 |

### 1.3 渲染

- 天空像素（visbuffer 为空的像素）采样天空视图 LUT，加上太阳圆盘和星空。
- 不透明物体和半透明物体都乘上空气透视。体积雾（§3）存在时，空气透视的结果并进雾的积分里，不重复计算。

### 1.4 天空作为光源

- ReSTIR 的 NEE 候选里包含天空（0010 §2.2）：按天空视图 LUT 的亮度建一张粗的 CDF（每帧一次），按它做重要性采样。
- radiance cache 的路径没有命中任何东西时，返回天空的辐射亮度。
- 云遮住天空的部分在 CDF 里用云的覆盖率衰减。

## 2. 体积云

### 2.1 模型

- 参考 Guerrilla 的 Nubis：
  - 天气图：覆盖率、云型、降水，是一张世界空间的 2D 图，可以随时间平流；
  - 云型：按高度剖面决定密度；
  - 细节：3D 噪声侵蚀。
- 天气图由游戏的天气系统驱动，渲染器只读它。

### 2.2 raymarch

- 在 1/4 分辨率上做，每帧更新其中一部分像素（时域交错），用上一帧的结果重投影补齐，再上采样到全分辨率。
- 步长自适应：空的区域大步跳过，进入云体后细步长。
- 光照：
  - 太阳：朝光源方向做几步短的 march，加上多次散射的近似（多个衰减倍频）；
  - 环境光：天空 LUT 按高度插值。
- 输出：云的颜色和透射率，以及一个近似的深度，用来和雾、半透明合成。
- 云的 raymarch 适合放在异步计算上。

### 2.3 档位

| 档位 | 分辨率 | 每帧更新比例 | 光照步数 |
|---|---|---|---|
| 低（NS2、XSS） | 1/4 | 1/16 | 3 |
| 中（PS5/XSX） | 1/4 | 1/8 | 5 |
| 高（PC High+） | 1/2 | 1/4 | 6 |

### 2.4 云阴影

- 一张俯视的云阴影图（太阳方向投影，2D），由天气图和密度算出。
- VSM 路径（L0–L2）和 ReSTIR 的太阳阴影射线（L3+）都乘上它；体积雾的太阳光照也用它。

## 3. 体积雾

### 3.1 froxel

- 视锥对齐的网格，例如 1080p 下 160×90×128，深度按指数分布。
- 每个格子存消光、散射反照率、自发光和相函数参数。

### 3.2 注入

| 来源 | 方式 |
|---|---|
| 全局高度雾 | 解析的高度衰减 |
| 局部雾体积 | Volume 材质（0011 §10.4）：按材质分箱，在覆盖到的格子上调度 `InjectVolume<M>` |
| 粒子 | 体积粒子把密度注入它覆盖的格子（§8.3） |

### 3.3 光照

- 每个格子：
  - 太阳：VSM（L0–L2）或者一条 RT 阴影射线（L3+），乘云阴影；
  - 局部光源：从 clustered 光源网格（0010 §5.4）里取这个格子的光源，用 RIS 选 1–4 个，L3 以上为选中的光源打 RT 阴影射线；
  - 间接光：查世界 radiance cache。
- 时域重投影累积，抖动格子内的采样位置。

### 3.4 积分与应用

- 沿深度做前向积分，得到每个格子到相机的累积散射和透射。
- 不透明物体、半透明物体、粒子按自己的深度从积分结果里采样。空气透视在这里合并（§1.3）。

## 4. 地形

参照 UE 5.8 的 Mesh Terrain（实验插件 MeshPartition 和 MeshTerrainMode）。它的核心思路是：**地形就是三角网格加一个非破坏的修改器栈，离线烘成普通的网格**。所以它天然支持洞穴、悬崖下凹、拱桥，运行时也没有专门的地形渲染路径。下面是 Marlin 的版本。

### 4.1 源数据

- **基础网格**：一个或多个三角网格，每个顶点带若干**权重通道**（float，例如草、岩石、泥、雪）。来源有：生成一块细分平面、导入高度图（导入后就只剩网格，高度图不保留）、转换一个现有网格。每块基础网格一个 `.masset`，按空间分块存放，方便多人同时编辑。
- **修改器**：每个修改器是关卡里的一个对象，有包围盒和优先级。

| 修改器 | 作用 |
|---|---|
| Patch | 把一块区域压平到某个高度，带衰减 |
| Noise | FBM 或正弦起伏 |
| TexturePatch | 用高度图纹理沿局部 Z 位移，同时写权重；可以先自适应细分 |
| Projection | 把顶点投射到一个用户网格上，可以顺带拷贝权重 |
| Spline | 沿样条的道路、河床：位移加衰减，可选内部平滑 |
| Boolean | 并、差、裁剪：挖洞、隧道、拱 |
| Lattice | 自由形变 |
| Remesh / Tessellate | 改拓扑：按目标边长重网格化，或者选择性细分 |
| SculptLayers | 雕刻笔刷的结果（§4.3） |
| WeightPaint | 刷权重通道 |

- **定义资产**（`TerrainDefinition`）：材质、优先级层的顺序、通道列表、每个平台的构建参数。

### 4.2 求值

- 顺序：基础网格 → 按优先级层 → 层内子优先级 → 对象路径（保证确定性）。
- 每个修改器声明它读写什么：顶点位置、拓扑、权重通道、UV。包围盒相交、且有读写冲突的修改器之间有依赖边，形成一个 DAG；没有依赖的并行求值（job 系统），改拓扑的修改器之间总是串行。
- 每个修改器实例的结果按"上游所有输入的哈希"缓存。改一个修改器，只有它下游的实例需要重算。
- 全部在 CPU 上做，只有通道纹理的栅格化用 GPU（§4.4）。这些都在 tools 和 editor 里，不进 runtime。

### 4.3 雕刻

- 笔刷：抬高、平滑、压平、坡度侵蚀。
- 雕刻作用在"求值到当前修改器为止"的网格上，结果存成**逐顶点的 3D 偏移层**（每层一个权重），不是 2D 高度图，所以悬崖下凹的地方也能雕。
- 重放时，把当前的地形顶点投射到雕刻时存下的网格上，按重心坐标插值偏移。上游的修改器变了，雕刻依然附着在大致相同的位置上。

### 4.4 构建（cook）

`marlin-cook-terrain` 是一个普通的 cook 插件（0003 §4.2），输入是基础网格、修改器和定义，cook 键是它们的内容哈希：

1. 把相邻的基础网格合并成**段**（顶点数有上限），在段内求值修改器栈；
2. 简化、重算法线，按世界分区的格子把段切成**单元**；
3. 每个单元产出：
   - 一个**普通的 cluster DAG 网格**（0009 §3）。单元边界上的顶点在 DAG 的所有层都锁定，所以相邻单元在任何 LOD 组合下都没有裂缝；单元是从同一张合并后的网格切出来的，边界本来就重合，不需要额外缝合；
   - 一个**远景代理**：按很大的目标边长简化的粗网格，给远处、HLOD 和 RT 远景用；
   - **通道纹理**：自动展开 UV（参考盒投影，悬崖下凹也能展开），在 UV 空间里把顶点权重栅格化成 `R8` 的纹理数组，每个在这个单元里非零的通道占一层，默认每米一个纹素；
   - **通道表**：通道 → 数组层的映射，5 位一项，打包进实例的每实例数据（0011 §7.3）；
   - **碰撞**：一张单独的三角网格，交给物理引擎，可以按平台简化。
4. 每个平台可以有不同的构建参数：段的大小、简化程度、远景代理的精度。

和 UE 的不同：UE 的 cook 直接用上一次在 editor 里构建好的结果，结果过期时只给一个警告。Marlin 把构建放进 cook，靠 cook 键保证结果总是最新的。editor 里的预览通过 cook 服务增量构建（0003 §6）。

### 4.5 editor 交互

- 改一个修改器时，旧包围盒和新包围盒碰到的**段**整段重建，段内没受影响的修改器直接用缓存。段越大，小改动的代价越高，所以段的上限是一个可调参数。
- **拖拽中的快速路径**：拖拽开始时，把被拖拽的修改器之前的所有结果冻结成一个临时的基础网格；拖拽过程中每一步只重新应用被拖拽的修改器，结果三缓冲，不阻塞视口。

### 4.6 渲染

- 运行时，地形单元就是普通的网格实例：进 GPU Scene、cluster DAG、visbuffer、材质解算和 ReSTIR，没有专门的地形渲染路径。
- **地形材质**是一个普通的 Surface 材质（0011 §2），用材质库里的辅助函数读通道：`TerrainChannels.Sample(ctx, channel)` 通过每实例数据里的通道表找到数组层，再按单元的 UV 采样。
  - 层的混合结果就是一棵 Substrate 树：一般是 `Horizontal` 的嵌套，或者把多个层在参数上混合成一个 Slab（更便宜）。
  - 世界单位的平铺 UV、陡坡和悬崖下凹处的三平面投影，都由材质库的辅助函数提供。
- **RVT**（0009 §6.3）：RVT 是俯视投影的，所以只缓存**朝上的表面**（法线和竖直方向的夹角小于阈值）的层混合结果。这些像素的材质解算直接采样 RVT；陡坡、悬崖下凹和洞穴内部仍然逐像素求值完整的材质。写进 RVT 的贴花（路面标线、车辙）也在这里混合。
- **光追**：每个单元的 BLAS 用它的 RT LOD（0009 §7）；远处的单元在 TLAS 里换成远景代理，RT 掩码标"地形"。
- **流送**：单元按世界分区的格子流送；cluster 页按 0009 §6.1 流送。远景代理常驻。

### 4.7 不做的

- 运行时变形（弹坑、可挖掘地形）：构建只在 tools 里，运行时只有烘好的网格。需要的话以后用顶点形变材质或者局部替换单元来做（§11）。
- 水体对地形的雕刻（湖、河床）可以用 Spline 和 Patch 修改器完成，不需要专门的水体修改器（水只是材质，§6）。

## 5. 植被

- 植被的实例和普通网格一样进 GPU Scene 和 cluster DAG（0009 §3–4）。大量实例按区块分组，实例剔除先按区块做。
- **几何**：尽量用不透明的几何建模叶片，而不是 alpha 卡片。cluster DAG 对几何植被很友好，而且不透明的几何对光栅、阴影和 RT 都便宜得多。
- **masked 叶片**：需要 alpha 卡片时走可编程光栅（0009 §4.4），RT 里在候选循环中做 alpha 测试（0009 §7）。
- **风**：顶点形变材质（`Deform`，0011 §2.2），在可编程光栅里求值。参数来自全局参数集（风向、强度）和每实例数据（相位）。
- **RT**：植被的 BLAS 用 RT LOD。远处的植被在 TLAS 里可以按距离退化成更粗的代理，或者干脆不进 TLAS（实例的 RT 掩码，0009 §7），只靠 radiance cache 提供它们的间接光贡献。
- **远景**：几何植被在很远处，DAG 简化到最粗一层也还是太多。远景要聚合成体素或者聚合的代理（UE 5.7 的 Nanite Foliage 就是这个方向，目前还是实验状态），细节待定（§11）。
- 摆放（PCG、绘制工具）不属于渲染器。

## 6. 水

- 水在渲染器里**只是材质**：水面是普通的网格（或者地形提供的面），材质用 `SingleLayerWater` BSDF（0011 §3.2）。
- **波浪和模拟属于物理引擎**：物理把位移或法线写进纹理（或者直接给出网格），水面材质的 `Deform` 和法线读它们。渲染器不做 FFT 和浅水模拟。
- `SingleLayerWater` 的光照：
  - 水面：镜面反射走 ReSTIR 和镜面追踪（0010 §2.7），低粗糙度的水面在 L3 以上走波前式完整材质；
  - 水下：吸收和散射系数按水体的光学深度衰减折射到的场景颜色；这需要 `WaterVolume` 特性（0011 §5.7），由引擎提供水面以下的场景颜色和深度；
  - 焦散：L3 以上用 RT 近似（水面法线向下投射、累积到一张焦散图）；L2 以下用动画纹理近似。
- 相机在水下时：水下雾用体积雾的一个局部体积实现，参数和水体的吸收、散射一致。

## 7. 毛发

### 7.1 资产

- groom 资产在 cook 时处理：
  - 发丝 → 线段；按空间把发丝分成簇，用于剔除和 LOD；
  - 按距离做发丝抽稀（远处保留部分发丝并加粗）；
  - 自动生成 card：把发丝簇烘成带 alpha、切线和深度的卡片纹理，给低档用。
- 毛发的物理模拟属于物理或动画系统，渲染器只接收模拟后的发丝顶点。

### 7.2 strand 渲染（PS5/XSX、PS5 Pro、PC Medium+）

- **光栅**：线段用软光栅写进一个独立的毛发 visbuffer。每像素保留最近的若干层（K-buffer，K = 4），每层是深度、发丝 id 和覆盖率，处理细发丝的半透明叠加。
- **深度不透明度**：从太阳和主光源的方向再光栅一次，得到深度不透明度图，用于自阴影和双散射（`HairShading` 特性，0011 §5.7）。
- **着色**：Hair BSDF（Marschner R/TT/TRT，加双散射近似）。
  - 直接光：太阳加 clustered 光源，阴影用深度不透明度和 VSM 或 RT；
  - 间接光：世界 radiance cache。
- **合成**：按 K-buffer 的层从后往前混合到场景颜色上，在 TSR 之前。毛发写进 reactive mask。

### 7.3 card 渲染（XSS、NS2、PC Low）

- card 是普通的 masked 几何，材质用 Hair BSDF，走 visbuffer 和材质缓冲，和其他不透明物体一样被 ReSTIR 照亮。

### 7.4 RT 代理

- strand 不进 BLAS。RT 用一组加粗的代理：从 card 的几何或者簇的包络管生成，只用于阴影和 GI（RT 掩码"毛发代理"，0009 §7）。

## 8. 粒子

`marlin-vfx` 负责模拟（GPU 上），渲染器提供三种渲染方式。粒子系统在每个发射器上选一种：

### 8.1 不透明网格粒子

- 发射器在 GPU Scene 里占一段动态实例范围；模拟直接把粒子的变换写进 `InstanceTransform`。
- 粒子和普通物体一样走 visbuffer、材质解算和 ReSTIR，光照完全一致。
- 实例数上限按发射器预分配，由模拟写出实际数量（间接参数）。

### 8.2 半透明 sprite 与 ribbon

- GPU 排序（按发射器内的深度做基数排序），走半透明前向（0009 §8），或者选择加权混合 OIT。
- 光照：clustered 光源网格加世界 radiance cache，不打射线。可以选逐顶点或逐粒子光照来降低开销。
- 可以画到半分辨率的目标里，再按深度感知上采样（0009 §8）。
- 写进 TSR 的 reactive mask。

### 8.3 体积粒子

- 烟、火、尘：不画面片，而是把密度、散射和自发光注入体积雾的 froxel（§3.2），和雾一起被照亮、积分。
- froxel 的分辨率有限，所以近距离的大烟团可以选择额外用一个局部的 3D 纹理做 raymarch（§11）。

### 8.4 接口

```rust
pub enum EmitterRender {
    Mesh { mesh: MeshId, material: MaterialInstanceId, capacity: u32 },
    Sprite { material: MaterialInstanceId, capacity: u32, sort: SortMode, oit: bool, half_res: bool },
    Ribbon { material: MaterialInstanceId, capacity: u32 },
    Volume { material: MaterialInstanceId, capacity: u32 },   // Volume 域的材质
}
```

- 发射器作为 `RenderScene` 里的一类对象，由 extract 写入；模拟的输出 buffer 是导入资源（0007 §2.3），在 graph 里声明读写。

  - groom 的抽稀和 card 生成：发丝数、覆盖面积守恒；
  - 粒子排序键的生成。
- **平台相关**：
  - 天空作为光源的重要性采样：累积结果和均匀采样的参考结果一致；
  - 体积雾的积分：均匀介质下和解析解比较；
  - strand 和 card 在中等距离上的覆盖率和平均颜色接近。
