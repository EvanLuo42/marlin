# 0009 — 环境、地形、植被、后处理与 GPU 粒子

状态：草案 · 2026-10-16

前置：[0006](0006-scene-renderer.md)、[0007](0007-material-system.md)。

## 0. 决定摘要

| 特性 | 决定 |
|---|---|
| 大气 | Hillaire 2020：透射率 LUT、多次散射 LUT、sky-view LUT、aerial perspective froxel |
| 体积雾 | froxel 网格：注入介质、计算光照、时间重投影、沿视线积分。Volume 域材质可以注入局部介质 |
| 体积云 | Nubis 式：天气图加噪声体积做 raymarch，低分辨率分帧更新并时间重投影。以后升级到体素化云（Nubis³ 的思路） |
| 地形 | 参考 UE Mesh Terrain：真 3D 网格，由非破坏式修改器栈生成，cook 成流式 cell 网格，走普通的 visbuffer 管线。材质用分层材质，结果合成进 RVT |
| 植被 | 普通 GPU Scene 实例加层级实例剔除。草由 GPU 每帧按 view 程序化生成。RT 中的 alpha 用 OMM 或通用 alpha 测试 |
| 后处理 | DOF → TSR → 运动模糊 → 曝光和 bloom → tonemap（自研，HDR 与 SDR 共用一条曲线）→ 调色 LUT → 输出编码 |
| GPU 粒子 | 模块写在文本 shader 里（实现粒子模块接口），emitter 是 .masset，编译器把模块融合成 kernel。不透明的网格粒子进 visbuffer |

## 1. 大气（天空）

- **模型**：
  - 行星半径加大气层厚度；
  - 瑞利散射和米氏散射，各自带指数高度分布；
  - 臭氧吸收层；
  - 地面反照率。
  
  这些参数都放在 `Atmosphere` component 里，由关卡或时间系统控制。
- **LUT**：
  - 透射率 LUT（256×64），参数变化时才重算；
  - 多次散射 LUT（32×32），同上；
  - sky-view LUT（192×108），每个 view 每帧重算，存相机附近的天空颜色；
  - aerial perspective：一个 32×32×32 的相机 froxel，存散射和透射，场景和半透明都用它做大气透视。
- **天空作为光源**：
  - 每帧从 sky-view 积分出天空辐照度（SH9），给探针用。
  - 低分辨率的天空 cubemap 供反射回退使用。
  - 高档和参考档另外从天空构建重要性采样图（等面积映射加层级 mip），给 ReSTIR 和 PT 采样天空光。
- **太阳和月亮**：方向光的颜色由大气透射率（相机位置处）决定。光源本身也会画成圆盘，带临边昏暗效果。
- **成本**：所有档位都开，档位只影响 LUT 分辨率。

## 2. 体积雾

- **froxel 网格**：与 clustered 光源共用视锥划分。分辨率按档位设置：中档 160×90×64，低档减半。深度方向按指数分布，覆盖到可配置的雾距离为止。
- **注入**：
  - 全局高度雾，参数化；
  - 局部雾体积：`FogVolume` proxy，带 Volume 域材质（0007 §6）。每个体积对它覆盖的 froxel 跑一次 `VolumeInject` 入口，写入消光系数、散射率、自发光和相函数参数。
  - 粒子也可以注入（§7.5）。
- **光照**（每个 froxel）：
  - 方向光：采样 VSM，再乘云阴影图；
  - 局部光：按 froxel 所在 cluster 查 clustered 列表，采样 VSM（可以降级为只采样较粗的一级 mip）；
  - 环境光：探针或 SHaRC 的辐照度，乘以相函数的平均值；
  - 相函数：Henyey-Greenstein，也可以选双瓣版本。
- **时间重投影**：每帧对 froxel 做抖动采样，和上一帧的结果混合，权重在 0.9 左右，消光系数变化大时降低权重。
- **积分**：沿深度方向逐层累积，得到 (in-scatter, transmittance)。
- **应用**：
  - 不透明表面：在光照合成时按深度采样；
  - 半透明：前向着色时逐像素采样；
  - 天空：远处的部分和 aerial perspective 合并。
- **参考档**：雾作为参与介质交给 PT，做真正的多次散射。

## 3. 体积云

### 3.1 建模（Nubis 式）

- **天气图**：2D 纹理，覆盖整个世界或在世界上平铺。通道包括：覆盖度、云类型（决定高度剖面）、降水（影响密度和颜色）。可以由时间系统驱动，也可以手绘。
- **噪声体积**：
  - 基础形状：128³，Perlin-Worley 加多个 Worley octave；
  - 细节：32³，Worley；
  - 2D curl 噪声：扰动细节，模拟湍流；
  - 都在 cook 期生成，以 3D 纹理形式存储。
- **密度函数**：
  - 天气图的覆盖度乘以高度剖面（来自类型梯度），先用基础形状腐蚀出大轮廓；
  - 再用细节噪声侵蚀边缘；
  - 风会让各层噪声按不同速度平移。

### 3.2 渲染

- 云层的 raymarch 在 **1/4 分辨率**下进行，每帧只更新 1/16 的像素（4×4 的棋盘轮换），其余像素用上一帧的结果重投影。
- **光照**：
  - 太阳光：沿光线方向做锥形采样的短 march（6 次），用 Beer-Powder 近似；
  - 多次散射：多个 octave 的近似；
  - 环境光：天空辐照度乘以高度相关的遮蔽。
- **步进**：自适应步长。空的区域用大步长，进入云体后改小步长。
- **深度**：输出 (散射颜色, 透射率, 加权平均深度)。平均深度用来和场景合成，也用来做 aerial perspective。
- **云阴影图**：从太阳方向俯视，输出透射率，给地面、VSM 方向光和体积雾使用。
- **与 ReSTIR 和 PT 的关系**：高档的 ReSTIR 只把云当作天空光的遮挡，查询云阴影图和天空的组合。参考档 PT 把云作为参与介质，做 delta tracking。
- **以后**：参照 Nubis³ 的思路，把美术指定的云（可以飞进去的近景云）做成体素化的距离场或密度场，cook 期生成，与天气图云混合。

## 4. 地形：参考 UE Mesh Terrain

### 4.1 UE 的做法（根据公开资料）

- UE 5.8 引入了实验性的 Mesh Terrain：地形是真正的 3D 网格，不再是 2.5D 高度场，所以可以做悬崖、洞穴、隧道和悬挑。
- 地形由**非破坏式修改器栈**生成：笔刷、重网格化、噪声、纹理、样条、网格、布尔运算。修改器可以像对象一样移动、复制和重新排序，挪动之后地形会自动重新生成。
- 分辨率可以不均匀：重点区域细，远处粗。
- 与 World Partition 和 PCG 集成。
- 已知的难点：竖直的射线可能穿过好几层表面，所以植被投射、导航网格生成和玩法查询都比高度场复杂。

### 4.2 Marlin 的数据模型

- 地形的**源数据**是一个 `TerrainSource` .masset，内容是修改器栈：
  - `BaseHeightfield`：高度图导入，或者程序化生成；
  - `SculptLayer`：雕刻数据，存成稀疏的窄带 SDF 增量；
  - `Spline`：道路和河流，可以抬升或下挖，并写入材质层权重；
  - `MeshStamp`：放进去的网格，与地形做布尔并集或差集；
  - `Boolean`：洞穴和隧道；
  - `Noise`、`Erosion`（侵蚀以后再加）；
  - `ResolutionRegion`：局部提高分辨率。
- **评估**：在编辑器里，修改器栈按区块评估成一个稀疏 SDF（窄带），每个区块独立评估并缓存。改动一个修改器，只重新评估它影响到的区块。
- **网格化**：对每个区块的 SDF 做 dual contouring 或者 adaptive surface nets 提取表面。顶点密度由 `ResolutionRegion` 和曲率决定。提取出的网格再交给 `cook_mesh` 做简化，并切成 meshlet。区块之间的公共边界顶点在简化时锁定，避免出现接缝。
- **cook 产物**：每个流送 cell 有若干个地形网格，按 0006 §2 的格式存储，包括 LOD 链和 meshlet；同时产出碰撞网格。运行时，地形网格就是一种普通的实例，几何形态是 `Terrain`（0007 §7.2），多出来的数据是层权重和 RVT 坐标。

### 4.3 运行时

- 进入同一条剔除和 visbuffer 管线，地形**不是特例**。
- LOD 就是普通的离散 LOD。cell 之间的接缝由 cook 期的边界锁定保证。不同 LOD 之间的边界靠 meshlet 级别的裙边，或者在 cook 期让相邻 LOD 的边界顶点对齐。
- **玩法查询**（`marlin-terrain`）：
  - 射线检测走物理碰撞网格，可以返回多个命中；
  - "某个 XZ 位置的地面高度"这类接口要显式选择：最高面、最近面，或者某个参考高度以下的第一个面。

### 4.4 材质与 RVT

- 地形材质是一个分层材质（0007 §8.5）。层权重来自两个地方：顶点上的权重，和 cell 的权重纹理（这张纹理用 cook 期自动展开的 UV）。
- **RVT（运行时虚拟纹理）**：
  - 投影方式是俯视 XZ 平面，页大小 128 px，分级 mip。
  - 合成：对于反馈请求的页，运行"地形分层材质的 `RvtCompose` 入口"，在这个入口里把所有层混合起来，结果写进物理页缓存。写入时用 GPU 实时 BC 编码，albedo 编成 BC1/BC7，法线编成 BC5，粗糙度等参数打包进同一个页。
  - 地形的 resolve 入口只需要采样 RVT，所以 resolve 的成本和材质层数无关。
- **悬挑和洞穴**：俯视投影没法表示这些表面。网格化时，按法线方向和"上方是否还有表面"给每个 meshlet 打一个 `no_rvt` 标记。被标记的 meshlet 在 resolve 里直接计算分层材质，并且用 triplanar 映射。也就是说，地形的 resolve 入口有两个变体：RVT 版和直接计算版。

### 4.5 植被摆放

- 在 cook 期（cook_level）做程序化摆放：按材质层权重、坡度、海拔和曲率生成实例，规则写在 .masset 里，类似 PCG 的规则集。
- 对 3D 地形，投射用的是网格表面上的随机点，不再是俯视射线，这样能避开多层表面的问题。

## 5. 植被

### 5.1 实例

- 树木、灌木、岩石都是普通的 GPU Scene 实例。为了支撑百万量级，实例剔除分三层：
  1. **cell**：CPU 侧对流送 cell 做视锥剔除；
  2. **实例簇**：cook 期按空间把实例聚成簇（每簇大约 64 个实例），每个簇带包围盒，GPU 先剔除簇；
  3. **实例**：簇通过后，再逐个剔除实例。
- **远处**：远处的树用较粗的 LOD。最远的一级是 impostor（八面体 impostor 图集），作为一种特殊的 meshlet（两个三角形）进入 visbuffer。材质 resolve 时，从 impostor 图集里取出 GBuffer 属性。

### 5.2 草与小型植被

- 草不进 GPU Scene。每帧每个 view 由 GPU 在相机周围的同心环里程序化生成：根据地形 RVT 的层权重决定密度，hash 出位置，写进一个瞬态实例 buffer，然后走 visbuffer 光栅。快速路径或者 WPO bin 都可以，风动用 WPO。
- 草不投射 VSM 阴影，或者只在近处投射；不进入 TLAS。AO 和接触阴影负责补足视觉效果。

### 5.3 透明度与光追

- **光栅**：
  - 近处的叶子优先用几何叶片，减少 alpha test 的 overdraw；
  - 远处用 alpha 卡片，进入 `opacity_mask` 的光栅 bin。
- **RT 中的 alpha**（`RtOpacity`，0007 §9）：
  - **有 OMM ext 时**：cook 期从 alpha 纹理和 UV 烘焙出 opacity micromap，附加到 BLAS 上。大部分微三角形可以直接判定为不透明或透明，硬件不需要回调。
  - **没有 OMM 时**：用 ray query 的候选三角形循环，对非不透明的候选做一次**通用 alpha 测试**：
    1. 从实例的材质槽查出提取好的 `(纹理, UV 通道, 通道, 缩放, 阈值)`；
    2. 用重心坐标插值出 UV，采样纹理；
    3. 和阈值比较，提交或者忽略这个候选。
    
    这样不用运行材质代码，也就不需要动态分发。
  - `opacity_mask` 无法归约成上面那种形式的材质，在 RT 中按不透明处理，cook 时报警。
- **风动**：植被材质的 `deform` 默认带 `RtIgnoreDeform`，BLAS 用静态形状。近处的大型树木可以按距离预算做 refit。
- **着色**：叶片用 Substrate slab，带 `thickness`（薄模式透射），相当于 UE 的 TwoSidedFoliage。树干是普通 slab。

## 6. 后处理链

### 6.1 顺序

```
HDR 场景颜色（线性 Rec.2020，渲染分辨率）
 → DOF（渲染分辨率，基于 CoC 的 gather，近景和远景分开处理）
 → TSR（上采样到输出分辨率，输出新的 history）
 → 运动模糊（输出分辨率：tile 最大速度 → 邻域速度 → gather）
 → 曝光直方图（从降采样的场景计算，自动曝光，单位 EV100，按物理相机参数计算）
 → Bloom（双滤波金字塔；高档可选 FFT 卷积，用于镜头光晕）
 → 镜头效果（暗角、色差，可选）
 → Tonemap + 调色 LUT（log 空间的 3D LUT）
 → 胶片颗粒
 → 输出编码（SDR：sRGB OETF；HDR：PQ 或 scRGB）+ UI 合成（0008 §6.2）
```

### 6.2 TSR（自研）

- **抖动**：Halton(2,3)。相位数随上采样比例变化，比例为 r 时用 8·r² 个相位。抖动会叠加到投影矩阵上，GPU Scene 的剔除和光栅不受影响。
- **算法**：
  1. 重投影：用 3×3 邻域里最近深度处的运动向量（速度膨胀）；
  2. 在 YCoCg 空间做邻域方差裁剪，修正历史颜色；
  3. 检测去遮挡：比较深度和上一帧深度，再检查速度一致性；
  4. 薄特征保护：检测亚像素级的细线，降低这些区域的历史拒绝；
  5. reactive mask：半透明和粒子写入，降低这些区域的历史权重；
  6. 用 Lanczos 系数的滤波器上采样。
- **动态分辨率**：一个控制器根据 GPU 帧时间（timestamp）调整渲染分辨率的比例，范围按档位设置（例如 0.5–1.0）。所有中间资源都按最大分辨率分配，用 viewport 和 scissor 来使用其中一部分，所以分辨率变化不会触发 render graph 的缓存失效，因为资源描述没有变。
- **厂商 ext**：DLSS、FSR、XeSS、PSSR 替代 TSR 这一步，统一使用 0004 §0 中规定的输入契约：颜色、深度、运动向量、抖动、曝光、reactive mask，以及给 Ray Reconstruction 用的 guide buffer。

### 6.3 Tonemap 与输出

- **工作空间**：线性 Rec.2020，场景单位是物理亮度（nits）乘以曝光。
- **tonemapper**：
  - 参数化曲线：趾部、线性段、肩部；
  - 色域映射：保持色相，把高饱和度的颜色压回目标色域；
  - 肩部的位置按目标显示器的峰值亮度自适应。SDR 的峰值是 100 nits，HDR 取显示器上报的峰值，或者玩家校准的值。
  - SDR 和 HDR 用**同一条曲线**，只是端点不同，所以两者观感一致。风格上参考 GT7 和 AgX 的思路。
- **调色**：3D LUT（33³），在 log 空间中应用，曲线前后都可以插入。LUT 由美术用 DCC 导出，或者由 PostProcess 域的材质生成。
- **HDR 输出**：swapchain 色彩空间用 HDR10（ST.2084）或 scRGB，从 RHI 查询显示器信息（0005 §1.5），游戏内提供校准界面。
- **PostProcess 域材质**（0007 §6）：可以插在若干固定位置：TSR 前、tonemap 前、tonemap 后。

## 7. GPU 粒子

### 7.1 创作模型

- **模块**：写在 Marlin shader 里，是实现了粒子模块接口的类型。模块可以提供以下阶段中的一个或多个：
  - `spawn`：输入 `SpawnContext`，修改当前粒子；
  - `update`：输入 `UpdateContext`，修改当前粒子；
  - `render_attributes`：给渲染提供属性。

  模块的参数和材质参数一样，通过反射交给编辑器和 cook（0007 §3）。
- **粒子属性**由各模块声明它们读写的属性，例如 `position`、`velocity`、`age`、`color`、`size`，以及自定义属性。编译器汇总所有模块用到的属性，得到 SoA 布局，没有用到的属性不占空间。
- **emitter**（.masset）由以下几部分组成：
  - 模块列表（有顺序），以及每个模块的参数覆盖；
  - 渲染器：Sprite、Ribbon、Mesh、Light；
  - 材质（`Usage` 里要声明对应的粒子形态，0007 §7.2）；
  - 容量、生命周期、LOD 和剔除设置。
- **数据接口**：引擎以 shader 接口的形式提供模块可以访问的外部数据：
  - 场景深度（用于碰撞）
  - 地形高度和法线
  - 骨骼网格表面采样
  - 曲线和渐变纹理
  - 向量场（3D 纹理）
  - MPC
- **编译**：cook 期把 emitter 的模块序列**融合**成 spawn kernel 和 update kernel，模块调用全部内联，属性布局固定。permutation 的单位是 emitter，参数不同的同一个 emitter 共用 kernel。

### 7.2 运行时数据

- 每个 emitter 实例在一个大的属性池里占一个固定容量的块，SoA 布局。
- 用一个 dead 列表（下标栈）管理空闲槽。spawn 时从 dead 列表弹出下标；粒子死亡时把下标压回去。
- alive 列表每帧在 update 里重新生成，用于渲染和排序。
- 每帧的 GPU 流程：
  1. **spawn**：生成数量由 CPU 给出的速率、burst 和 GPU 侧的事件计数共同决定，结果写进间接参数；
  2. **update**：处理 alive 粒子，死亡的写回 dead 列表；
  3. **compact**：生成新的 alive 列表；
  4. **bounds**：用于剔除和 VSM 失效计算，结果延迟一帧回读。
- CPU 侧只管理 emitter 实例：创建和销毁、按距离做 LOD 和剔除（用上一帧的 bounds）、播放状态。也就是说，CPU 不接触单个粒子。

### 7.3 渲染

| 渲染器 | 路径 |
|---|---|
| Sprite（不透明或 masked） | mesh shader 从 alive 列表生成四边形，进入 visbuffer。几何形态是 `ParticleSprite`，因此会参与 GI 和阴影 |
| Sprite（半透明） | 按 emitter 排序后做前向着色；emitter 内部用 GPU 基数排序按深度排序（可选）；MBOIT 可选；写 reactive mask |
| Ribbon | 按粒子的生成顺序连成条带，用 mesh shader 生成几何 |
| Mesh | 每个 alive 粒子作为一个实例进入一次剔除和 visbuffer，几何形态是 `ParticleMesh`。粒子的变换由 resolve 从粒子 buffer 中读取 |
| Light | 粒子光源写进一个有上限的光源列表，并入当帧的 clustered 光源。ReSTIR 档把它们并入光源采样结构 |

- 半透明粒子的光照可以按粒子做：在 update 阶段，或者用一个单独的 pass，对每个粒子在中心点采样一次 clustered 光源、探针和雾，结果作为属性传给像素着色。每像素逐光源计算是一个可选的高质量模式。

### 7.4 碰撞与事件

- **深度缓冲碰撞**：用上一帧的深度和法线，屏幕外没有碰撞。
- **地形高度碰撞**：使用数据接口。
- **事件**（死亡、碰撞）写进 GPU 事件队列，可以触发其他 emitter 的 spawn，全程在 GPU 上完成。回读到 CPU 的事件（例如播放音效）有延迟，并且数量有上限。

### 7.5 与体积雾

- emitter 可以选择把密度注入 froxel，比如烟雾。粒子以球形核的方式写进覆盖到的 froxel，作为一种体积注入源（§2）。

## 8. 测试

- **大气**：LUT 与离线参考积分对比（CPU 端用 f64 做 Hillaire 的积分），FLIP 和相对误差都设阈值。
- **体积雾**：均匀介质的透射率与解析解对比。
- **云**：静态天气图下，固定种子、关闭时间重投影，与黄金图做 FLIP 对比；另外检查分帧更新收敛后，与"每帧全量更新"的结果一致。
- **地形**：
  - 修改器栈评估和网格化的确定性：同样的输入得到逐字节相同的网格；
  - 区块边界无裂缝：相邻 cell 的边界顶点完全一致；
  - 多层查询的正确性。
- **TSR**：静止场景收敛后与超采样参考对比（FLIP）；去遮挡区域的重影指标。
- **粒子**：
  - 模块融合后的 kernel 与逐模块执行的结果一致（固定种子，逐字节比较）；
  - dead 和 alive 列表的守恒：alive 数 + dead 数 = 容量。

## 9. 待定问题

1. Mesh Terrain 的 SDF 区块大小与网格化算法（dual contouring 还是 surface nets），要看雕刻笔刷的手感和性能。
2. RVT 合成时实时 BC 编码的质量和成本，需要实测。主机上也许可以直接用未压缩的格式。
3. 体积云要不要在中档就切换到体素化云。
4. 草的程序化生成与 VSM 缓存的交互：草每帧都在变，不应该让静态页失效。初步的方案是草不投影，或者只写进动态层。
